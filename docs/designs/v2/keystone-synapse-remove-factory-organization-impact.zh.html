开发设计影响面梳理 / 先拆除，再接入 Workspace

Keystone / Synapse 去工厂与组织概念

核心判断：工厂和组织不是孤立 CRUD，而是当前 Keystone 边缘数据模型里的归属、筛选、去范式索引和任务配置来源；要先隐藏和停止新增概念，再以 Hilbert workspace 接管数据归属，最后清理数据库字段与接口。

影响系统keystone, synapse
未来归属hilbert workspace
当前风险高：任务链路依赖字段
建议方式分阶段迁移
01

背景与问题

现在的 Keystone / Synapse 仍保留“环境层级”：factories 表、organizations 表，以及大量 factory_id、organization_id 字段。历史设计已经经历过一次层级反转：工厂代表边缘部署的物理边界，组织代表租户；但接下来系统会引入 Hilbert 的 workspace 作为统一工作空间边界，因此工厂和组织在 Keystone / Synapse 中不再应作为一等业务概念出现。

Hilbert 当前 workspace 模型包含 id、name、description、admins_str、members_str、创建人与更新时间；前端通过全局 selectedWorkspaceId 作为业务页面请求参数。这个模型更接近“权限与业务归属边界”，而不是“物理工厂位置”或“组织租户”。

本文只分析去除 Keystone / Synapse 中工厂与组织概念的影响面，不实现代码，也不定义 Hilbert 与 Keystone 的最终认证集成协议。
02

目标与非目标

目标

  • 移除 Synapse 后台中的工厂管理、组织管理入口、路由、页面、表单字段和筛选器。
  • 移除 Keystone 暴露给前端的 /factories、/organizations 管理 API 及相关 handler 注册。
  • 识别所有依赖 factory_id、organization_id 的创建、查询、展示、测试和同步链路。
  • 给出 workspace 接管后的字段、接口、迁移和验证顺序。

非目标

  • 不在本阶段重写 Hilbert workspace 本身的管理能力。
  • 不立即删除所有数据库中的归属字段；任务、批次、episode、同步链路需要兼容迁移窗口。
  • 不改变 Axon recorder / transfer 的 WebSocket 协议，除非后续明确任务配置不再需要返回 factory 名称。
  • 不清理全部历史 Markdown 设计文档，只更新 OpenAPI、Swagger 和会误导当前开发的活跃文档。

Keystone 影响清单

数据库与迁移

对象当前字段建议处理
factories实体表。最终删除；过渡期只读或保留 legacy 映射。
organizationsfactory_id, name, slug, settings。最终由 workspace_id 取代；不要继续开放 CRUD。
scenesfactory_id 必填。改为 workspace_id 或取消归属；如果场景全局共享，则删除归属过滤。
robotsfactory_id 必填。如机器人属于 workspace，则加 workspace_id；如机器人是边缘全局资产，则取消前端必填。
data_collectors, inspectorsorganization_id 必填。改为 workspace_id，并接入 Hilbert workspace 成员权限。
workstationsfactory_id, organization_id 去范式。建议改为 workspace_id 去范式；从采集员或显式选择派生。
orders, batches, tasks, episodesorganization_id / factory_id 用于筛选与统计。先加 workspace_id 双写和回填，验证统计一致后删除旧索引。
device_id_sequencesfactory_id + robot_type_id 唯一。改为 workspace_id + robot_type_id，或改成全局序列。
sync_logssource_factory_id。短期保留为历史字段；新增 source_workspace_id 后再迁移。

API Handler 与路由

  • internal/server/server.go：移除 FactoryHandler、OrganizationHandler 初始化、字段和路由注册；确保 /api/v1 其他 handler 不再依赖它们。
  • internal/api/handlers/factory.go、organization.go：停止暴露或删除管理 API；Swagger 需要重新生成。
  • scene.go、robot.go：创建/更新当前强依赖 factory_id 和 factories 存在校验。
  • data_collector.go、inspector.go：创建当前强依赖 organization_id 和 organizations 存在校验。
  • order.go：CreateOrderRequest 当前要求 organization_id，并校验 organization 与 scene 属于同一 factory。
  • batch.go、task.go：批次和任务从 order/workstation 派生归属字段；如果旧字段置空，会影响 dashboard、列表、episode 生成。
  • production_dashboard.go：scope 支持 factory_id、organization_id 查询参数；需要改成 workspace_id 或只保留 workstation scope。
  • device_registration.go：入参 factory、响应 factory_id、设备 ID 格式、序列表全部需要改。

Axon 与任务配置边界

TaskConfig 当前返回 factory 字段，GetTaskConfig 会 JOIN factories 并在缺失时返回冲突错误。若 Axon recorder 仍消费该字段，后端不能简单删除；需要先确认 recorder 端是否只展示该名称，还是用于路径、上传、回调或设备侧校验。

Synapse 影响清单

必须删除或改向的入口

  • src/router/index.js：当前 /admin 默认重定向到 /admin/factories，需要改到 dashboard、scenes、robots 或未来 workspace-aware 首页。
  • src/components/layout/AdminSidebar.vue：移除“工厂管理”“组织管理”两个导航项；环境管理保留场景/子场景。
  • src/views/admin/factories/*、src/views/admin/organizations/*：页面可删除或保留为迁移期隐藏页面；不应再作为可访问业务入口。
  • src/api/factories.js、src/api/organizations.js：如果后端移除 API，前端也应删除调用；若保留 legacy mapping，则命名必须改成 legacy，避免继续扩散概念。

06

接口与数据模型迁移建议

推荐目标模型

如果 workspace 是未来统一归属边界，建议 Keystone 中所有需要隔离、筛选、权限控制的业务对象统一使用 workspace_id。不需要归属的物理资源保持全局，不要为了替代 factory 而机械加字段。

当前概念建议替代说明
organization_idworkspace_id采集员、检查员、订单、批次、任务、episode 的业务归属边界。
factory_id多数情况下删除；必要处改 workspace_id机器人、场景是否归 workspace 需要产品确认；不要默认等价替换。
factory_nameworkspace_name 或不返回任务配置和详情展示需逐项验证。
source_factory_idsource_workspace_id同步日志可兼容保留历史字段。

接口改造原则

  • 前端业务请求统一传 workspace_id，或由 Keystone 从 Hilbert token / session 中解析当前 workspace。
  • 列表接口的 factory_id、organization_id query 参数进入 deprecated 窗口，新增 workspace_id。
  • 创建接口优先要求 workspace_id；如果 workspace 来自登录上下文，则请求体不再需要归属字段。
  • 响应体过渡期可同时返回旧字段与新字段，但 Synapse 只能消费新字段，避免继续绑定旧概念。
  • Swagger 需要随 handler 注释重新生成：swag init -g internal/server/server.go -o docs。
07

风险与关键问题

风险表现缓解
任务链路中断 创建批次/任务时无法派生 factory 或 organization，导致任务配置、dashboard、episode 生成失败。 先新增 workspace_id 双写；验证任务创建、回调、上传、QA、同步全链路后再删除旧字段。
设备注册 ID 变化 现有设备 ID 编码含 factory ID，去掉工厂会改变序列作用域和展示格式。 单独设计设备注册协议，保留旧 ID 兼容解析；新设备使用新格式。
权限边界不清 Keystone 当前没有完整 workspace 权限模型；只删组织会让采集员/检查员归属失效。 先定义 Keystone 如何获取 Hilbert workspace：token claim、API 校验、还是本地缓存。
前端隐藏不等于移除 路由隐藏后，其他页面仍调用 factories / organizations API 获取下拉选项。 以 API 调用为准做清理，构建时通过 rg 检查旧关键词。
历史数据筛选退化 删除旧索引后，历史任务和 episode 无 workspace 归属，统计不可筛选。 迁移脚本根据 organization/order/workstation 关系回填 workspace；无法映射的数据进入默认 workspace 或隔离队列。

需要产品 / 架构确认的问题

  1. Workspace 是 Keystone 本地表，还是完全来自 Hilbert 并由 Keystone 缓存？
  2. Synapse 是否会拥有 workspace selector，还是只运行在单 workspace 上下文？
  3. 机器人、场景是 workspace 私有资源，还是边缘实例全局资源？
  4. Axon recorder 的任务配置是否仍需要 factory 名称？
  5. 已有设备 ID 中的 Fxxxx 是否需要长期兼容和展示？
08

建议实施顺序

Phase 0：冻结旧概念入口

  • Synapse 移除工厂/组织导航和默认重定向，停止新增 factory / organization。
  • Keystone 可先保留旧 API 但标记 deprecated，或只对内部迁移开放。
  • 增加回归检查：前端不再出现“工厂管理”“组织管理”入口。

Phase 1：引入 workspace 字段与兼容层

  • 为需要归属的 Keystone 表新增 workspace_id 和索引。
  • 创建/更新接口支持 workspace_id，旧 organization_id 只做兼容映射。
  • Synapse 表单和筛选改为 workspace；删除 factories / organizations 下拉调用。

Phase 2：迁移任务链路

  • 批次、任务、episode 生成时写入 workspace_id。
  • dashboard、统计、数据运维、同步列表全部改用 workspace scope。
  • 设备注册单独迁移序列策略，避免与任务链路混在同一个 PR 中。

Phase 3：删除旧实体与字段

  • 删除 factory.go、organization.go handler 和 Swagger 路由。
  • 删除 Synapse 工厂/组织页面、API 文件、option adapter。
  • 删除数据库旧字段和索引，或保留只读 legacy 字段直到历史数据归档完成。
09

验证清单

  • Keystone：go test -cover -race -v ./...，重点关注 order、batch、task、robot、scene、collector、inspector、dashboard、device_registration 测试。
  • Keystone：重新生成 Swagger 后确认 /factories、/organizations 不再出现在公开 API，或明确标记 deprecated。
  • Synapse：npm run build，并手动走 admin 登录、机器人创建、场景创建、采集员创建、订单创建、批次创建、大屏。
  • 数据迁移：抽样校验旧 organization_id 映射到 workspace_id 的订单、批次、任务、episode 数量一致。
  • 端到端：创建订单 → 创建批次 → 生成任务 → recorder 获取 task config → 完成回调 → transfer 上传 → episode QA → dashboard 统计。
结论：可以先从 Synapse 管理入口和 Keystone 公开 CRUD 开始“去概念化”，但不能直接删除所有 factory_id / organization_id 字段。真正的安全路径是让 workspace_id 接管归属和筛选，再逐步清理旧实体、旧 API、旧 UI 与历史索引。
