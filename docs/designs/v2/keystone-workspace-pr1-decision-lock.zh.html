01

背景与问题

Keystone 正在从本地组织模型迁移到 Hilbert Workspace 模型。这里的关键压力不是字段重命名， 而是所有权迁移：Workspace 的事实来源必须从 Keystone 本地 CRUD 转移到 Hilbert。

PR-1 只解决 Workspace 来源规则。它不迁移业务表归属，不重建设备模型，也不处理任务、Episode、raw data、dataset 的主链路语义。

已完成的第一击：PR-1A

  • Keystone 后端具备 id=0 default workspace。
  • GET /workspaces 和 GET /workspaces/:id 只读可用。
  • V2 baseline schema 已支持 source、upload_enabled、last_synced_at。

后续的连续技

  • PR-1B 接入 Hilbert service identity bootstrap 和 workspace sync。
  • PR-1C 让 Synapse 使用全局 Workspace Selector 和只读状态页。
  • PR-2 之后再迁移业务表 organization_id -> workspace_id。
02

目标与非目标

目标

  • 建立 Workspace 来源规则：Hilbert 是源头，Keystone 是投影消费者。
  • 保留 id=0 default workspace，支持未配置 Hilbert 时的本地闭环。
  • 禁止 default workspace 进入 Hilbert / 云同步。
  • 定义 PR-1B 的临时 bootstrap 与正式鉴权替换边界。
  • 定义 Synapse 在 PR-1C 中的只读选择器行为。

非目标

  • 不提供 Keystone 本地 workspace 创建、编辑、删除。
  • 不修改业务表的 organization_id。
  • 不同步 Hilbert dc_device、dc_plan、raw_data、dataset。
  • 不把 Hilbert admins/members 接入 Keystone 本地权限。
  • 不自动把 default 数据补绑或上传到 Hilbert workspace。

PR-1B 鉴权边界

Keystone 的真实身份应是 Hilbert 中被授予若干 Workspace scope 的独立服务身份。 由于 Hilbert 暂未提供正式 Keystone 鉴权，PR-1B 允许临时配置一个 Hilbert 管理员账号的 code/password 作为 service identity bootstrap。 

HilbertServiceIdentityProvider
  BootstrapPasswordProvider   (PR-1B temporary)
    GET /v1/console/nonce/generate
    POST /v1/console/account/login
    sessionKey kept in memory only

Future provider
  app credential / token exchange
  same workspace sync service contract
  • 代码和配置使用 service identity 命名，不使用 admin 命名。
  • PR-1B 不引入多模式配置；只要求 password login 不泄漏到 workspace sync 逻辑里。
  • 临时 bootstrap account 应是 Hilbert system admin，或目标 workspaces 的管理员账号。
  • PR-1B 使用 Hilbert 当前的 list-available 返回值，不本地强校验 admins 是否包含 bootstrap account。
  • 正式鉴权阶段应让 Hilbert 审计中能区分 Keystone service identity 和人工管理员。

05

同步算法与 API

PR-1B 同步算法

  1. Ensure id=0 default workspace exists.
  2. 如果 HilbertConfig 的 BaseURL、ServiceAccountCode、ServiceAccountPassword 不完整，启动同步跳过；手动同步返回 503。
  3. 通过 service identity provider 登录 Hilbert，获得内存 sessionKey。
  4. 调用 GET /v1/console/workspace/list-available。
  5. 先校验全部记录：id > 0、name 非空、无重复 ID。
  6. 校验通过后开启事务，upsert 全部 Hilbert workspaces。
  7. 提交事务；本轮未返回的 Hilbert workspace 不删除、不禁用。
Upsert mapping
  id                 <- Hilbert WorkspaceVO.id
  name               <- WorkspaceVO.name
  description        <- WorkspaceVO.description
  source             <- "hilbert"
  upload_enabled     <- true
  admins_str         <- hash-wrapped normalized WorkspaceVO.admins
  members_str        <- hash-wrapped normalized WorkspaceVO.members
  last_synced_at     <- Keystone sync time
  hilbert_created_at <- WorkspaceVO.createdTime
  hilbert_updated_at <- WorkspaceVO.updatedTime
  • Hilbert 返回 id=0 或非法记录时，本次 sync 整体失败，不 upsert 任何记录，本地缓存保持不变。
  • admins/members 继续以 hash-wrapped admins_str/members_str 存储，只做 trim、drop-empty、dedupe，不做严格业务校验。
  • created_at/updated_at 保留 Keystone 本地投影行时间；Hilbert 原始时间写入 hilbert_created_at/hilbert_updated_at。
  • upload_enabled=true 仅表示来自 Hilbert sync 且可进入 Keystone 云同步候选集，不保证后续 raw data / dataset 创建一定成功。

07

风险、权衡与验证

权衡

  • default workspace 使用真实 DB 行，而不是虚拟 API 对象，便于后续业务表以 workspace_id=0 形成一致外键语义。
  • Hilbert sync 只 upsert 不删除，优先保护历史可见性；撤权、下线和 access status 后置。
  • 临时 password bootstrap 封装在 provider 内，给正式服务身份鉴权留下替换点。

风险

  • 删除本地 workspace 写路由是行为变化，依赖本地组织管理的旧 UI 必须同步迁移。
  • PR-1B 使用 list-available，不是严格的 manageable workspace 列表。
  • default 数据后续必须通过显式人工补绑进入 Hilbert workspace，不能自动上传。

PR-1 必须满足

  • 未配置 Hilbert 时，GET /workspaces 返回 id=0 的 default workspace，且 upload_enabled=false。
  • Hilbert 同步成功后，GET /workspaces 返回 default 加本地缓存的 Hilbert workspaces。
  • Hilbert 后续失败时，GET /workspaces 仍返回上次缓存加 default；手动 sync 返回失败。
  • Swagger 不暴露 workspace 创建、更新、删除接口。
  • Synapse selector 展示 default，但明确标记本地和不可云同步。
  • cloud sync worker 和任何 Hilbert raw data / dataset 创建路径必须拒绝 workspace_id=0。
  • 云同步资格统一使用 workspace_id != 0 && source='hilbert' && upload_enabled=true。

测试与文档

  • PR-1A 已新增 workspace handler 单测，覆盖 default 返回、workspace_id=0 过滤和写路由不存在。
  • PR-1B 需要继续新增 Hilbert sync upsert、缓存保留和手动 sync 失败场景测试。
  • PR-1A Swagger 只应出现 GET /workspaces 和 GET /workspaces/{id}。
  • PR-1B 完成后，Swagger 中应再出现 POST /workspaces/sync。
