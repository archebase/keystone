01

核心判断

登录只回答“你是谁”；工作上下文激活才回答“你现在操作哪个工位和设备”。

当前设备绑定登录把账号认证、工位选择、机器人作用域和会话占用放在同一次登录中。在多人轮班共享设备场景下，这会导致换设备必须重新走设备专属登录、Web 与 EgoPortal 各自维护绑定逻辑，并让人员身份与设备生命周期互相污染。

本方案采用最小的两阶段认证：先得到不含工位作用域的人员令牌，再通过统一的工位激活模块换取现有格式的 workstation-scoped JWT。Web 由用户选择工位；EgoPortal 使用已注册 iPhone 的设备凭证自动解析工位。不新增独立租约系统。

02

范围与边界

本期目标

  • 人员登录不再要求提交任意设备 ID。
  • Web 登录后直接展示本人可用工位并完成选择。
  • EgoPortal 保留共享 iPhone 的设备凭证，人员登录后自动激活对应工位。
  • 生成包含 canonical workstation、robot、workspace 的工位作用域 JWT。
  • 复用 workstations.is_current 和数据库唯一约束保证同一设备只被一人占用。
  • 支持正常退出和管理员强制释放；第一版不建设心跳租约系统。

本期不做

  • Web 不做二维码和短码激活。
  • 不允许普通数采员抢占仍被其他人员占用的工位。
  • 不改变 Axon Recorder / Transfer 的设备认证。
  • 不让前端提交 robot_id、workspace_id 作为可信授权事实。
  • 不把未上传历史数据改写为下一位数采员的归属。
  • 不新增 work_context_sessions、专用 heartbeat 或一次性设备证明。
  • 不在本期建设完整企业 SSO 或工牌系统。
03

统一认证模型

identity token

证明人员身份。包含 collector、operator、role，不包含 workstation、robot、workspace。

用于查询本人信息、可用工位、计划概览和历史记录。

device credential

证明设备身份。EgoPortal 的共享 iPhone 和 Axon 分别持有自己的长期设备凭证。

人员退出时不得删除设备凭证。

workstation token

证明人员当前操作某个 canonical 工位。复用现有 JWT claims，包含 workstation、robot、workspace，不引入 context_session_id。

用于 next-task、Recorder 控制、正式采集和需要工作作用域的写操作。

identity token claims
  collector_id
  operator_id
  role

workstation-scoped token claims
  collector_id
  operator_id
  workstation_id
  robot_id
  workspace_id
  role

Web 流程：直接选择工位

人员登录
POST /api/v1/auth/login 只认证账号密码并返回不含 workstation claims 的 identity token。
获取候选
GET /api/v1/auth/me 根据 Hilbert 当前有效计划的 operator + dc_device_id 返回本人可用工位及占用状态；后续如需人工授权，再增加显式授权关系。
选择工位
页面展示工位名称、机器人名称、设备名称、在线状态和占用状态。前端只提交 workstation_id 候选值。
服务端激活
POST /api/v1/auth/workstation/activate 在事务内重新验证计划资格、Workspace 访问权和设备占用状态，并切换 is_current。
进入工作台
前端使用返回的 workstation-scoped access token，计划刷新、任务准备和设备控制继续走现有鉴权链路。
workstation_id 是用户选择，不是授权事实；is_current 是占用状态，也不是长期授权。Keystone 必须从 Hilbert 计划或显式授权验证资格，并从数据库解析 robot_id 与 workspace_id。

05

EgoPortal：设备自动激活

共享 iPhone 在首次部署时使用 device_auth_token 完成设备注册，并将长期设备凭证保存在 Keychain。每位数采员接班时只登录自己的账号；App 不展示其他工位，也不要求扫码。

01 · 设备常驻设备凭证跨班次保留，人员退出不会清除。
02 · 人员登录账号密码换取不含设备作用域的 identity token。
03 · 自动定位App 调用统一激活接口，同时提交人员令牌和 Keychain 中的设备凭证。
04 · 激活工位Keystone 验证人员计划资格与设备身份，返回 workstation-scoped token。
POST /api/v1/auth/workstation/activate
Authorization: Bearer <identity token>
Device-Authorization: <device credential>

Keystone resolves:
   device -> robot -> workstation -> workspace
   then validates current Hilbert plan/operator eligibility
   and activates the canonical workstation
第一版由 Keystone 在一次 HTTPS 请求中同时验证人员令牌和设备凭证。只有未来设备凭证被封装在不可导出的 SDK 或安全模块中时，才增加一次性 device proof。

共享 iPhone 交班规则

  • 允许用户主动勾选“记住密码”；密码保存在 iOS Keychain，App 重启后重新执行人员登录与设备自动激活。未勾选时不保存密码。
  • 设备凭证、设备配置和未上传 capture_session 保留。
  • 已有 capture_session 继续保存采集开始时的 operator 快照。
  • 后台上传使用设备凭证和 manifest 快照，不要求上一位数采员继续登录。
  • 人员随时可以退出；active capture 继续保留原 operator 快照并由设备凭证完成上传。
  • active capture 存在时禁止下一位人员普通接管工位；管理员强制接管必须记录原因。
06

占用与交班控制

场景Keystone 行为客户端表现
工位无人占用事务内把对应 workstation 设为 is_current=true。进入工作台。
同一人员重复激活同一工位幂等返回新的 workstation-scoped token。恢复工作台。
其他人员正在占用依赖 current robot 唯一约束并返回 409 workstation_occupied。显示占用人员并等待或联系管理员。
人员正常退出立即删除客户端人员令牌，并将当前 workstation 释放；退出本身不被 active capture 阻止。回到登录页，设备凭证和本地数据保留。
存在 active capture阻止下一人普通接管，但不阻止上一人登出。等待采集完成或请求管理员处理。
管理员强制释放清除 is_current 并记录操作者、原因和时间。旧 token 在下一次请求时立即失效。

第一版时效策略

  • 人员 identity token 和 workstation token 按一个班次配置，建议 8 小时；仍由现有 JWT 配置统一控制。
  • 每次 workstation-scoped 请求继续查询 is_current，因此管理员释放可立即生效，无需等待 JWT 过期。
  • 第一版不做专用 heartbeat 和自动超时接管，避免浏览器后台与 iOS 挂起造成假掉线。
  • 如果实际运营出现大量异常退出，再增加 last_seen_at，仅在无 active task/capture 且长时间无业务请求时允许安全回收。

接口与数据模型

接口令牌职责
POST /auth/login无人员认证，返回不含 workstation claims 的 identity token。
GET /auth/meidentity / workstation返回身份，以及由 Hilbert 当前计划或显式授权推导的可用工位。

资格与状态必须分开

eligible workstation
  = Hilbert 当前有效 dc_plan(operator + dc_device_id)
    OR 未来新增的显式授权关系

current occupancy
  = workstations.is_current

historical ownership
  = task / capture / episode operator snapshot

第一版不新增 work_context_sessions。激活事务锁定 robot/workstation 相关行，复用现有 current robot 唯一索引处理并发；可选增加 activated_at、last_seen_at、client_type，但不要求建立独立状态机。

10

迁移与兼容

  1. Keystone 两阶段认证：登录先签发不含 workstation claims 的 identity token；新增统一工位激活接口并复用现有 workstation-scoped JWT。
  2. Synapse Web：登录页只收账号密码；登录成功进入工位选择页；只有一个可用工位时可自动激活，但仍展示确认结果。
  3. Web 写操作收口：next-task、Recorder RPC、任务配置等接口继续要求带 workstation claims 的 token。
  4. EgoPortal：激活请求同时携带 identity token 与设备凭证；可选记住密码只保存在 Keychain；采集开始/结束同步任务状态，上传继续使用 operator 快照与设备身份。
  5. 失效联动：工位重新分配、管理员释放和正常退出统一更新 workstations.is_current，现有中间件立即拒绝旧 token。
  6. 清理兼容逻辑：两个客户端稳定后，移除登录请求中的 device_id；不再维护登录即绑定设备的分支。
迁移期新旧路径必须共用 workstations.is_current 和 current robot 唯一约束，不能建立第二套会话事实来源。

测试与验收

  • Web 用户登录后只能看到服务端分配给自己的工位。
  • 修改请求中的 workstation_id 不能激活未分配工位。
  • 候选工位由 Hilbert 当前计划或显式授权产生，不依赖 is_current。
  • 同一工位被另一人员占用时返回明确 409，数据库中不会出现第二条 current robot 绑定。
  • Web 关闭并重新打开页面时，可用 identity token 重新选择工位；异常占用可由管理员释放。
  • EgoPortal 人员登录后自动解析当前 iPhone 对应工位，不展示其他工位。
  • EgoPortal 设备凭证无效时阻止正式采集，不回退到人工选择其他设备。
  • 人员退出后 identity/workstation token 被删除，但设备凭证和未上传采集不丢失。
  • 换班后历史 capture、manifest、episode 仍保留原 operator 快照。
  • 录制中允许人员退出，但下一位人员无法普通接管；管理员强制接管产生审计记录。
  • Axon Recorder / Transfer 连接不受人员登录变化影响。
  • 旧登录路径在迁移期与新激活路径共用同一 is_current 互斥规则。
12

风险与取舍

选择本方案的原因

  • Web 无需摄像头、扫码或设备短码。
  • EgoPortal 不允许用户手动选择不属于当前 iPhone 的工位。
  • 人、设备、工位三类身份生命周期互不污染。
  • 服务端通过现有 is_current 校验即时撤销工位权限，不必等待 JWT 自然过期。
  • 未来增加短码、工牌或 SSO 时，只需增加激活适配器。

主要风险

  • 计划数据短暂不可用：保留最近一次 Hilbert 投影用于展示，但激活前必须重新验证本地有效投影。
  • 异常退出残留占用：第一版由管理员释放；确认频率足够高后再引入安全的 idle 回收。
  • 资格与占用混淆：代码和查询必须坚持计划/授权决定 eligibility，is_current 只决定 occupancy。
  • 设备凭证泄漏：只存 Keychain，走 HTTPS，服务端保存哈希并支持轮换。
  • 强制接管影响 active capture：默认禁止，管理员操作必须带原因并保留原 operator 快照。
最终决策：两阶段认证但不建设独立租约系统；Web 选择工位，EgoPortal 用设备凭证自动定位，Keystone 复用现有 workstation-scoped JWT 与 is_current 互斥。
