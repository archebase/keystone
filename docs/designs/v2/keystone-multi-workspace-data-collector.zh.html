IMPLEMENTATION DESIGN / DECISION LOCK

一个身份
多个 Workspace

Keystone 以全局数采员身份承接 Hilbert 账号，以 Workspace 的 admins/members 作为唯一归属事实；数采员登录后直接看到所有相关资源，不执行 Workspace 选择。

01

核心判断

采用“全局 data_collectors + 结构化 workspaces.admins/members”。不复制用户身份，不重复保存归属关系，也不建设通用 RBAC。

为什么这是最小正确模型

身份稳定

同一个 Hilbert account 在 Keystone 只有一个 data_collector_id。JWT、工位、任务审计和统计可以稳定引用同一身份。

关系真实

一个数采员可属于多个 Workspace，一个 Workspace 也可包含多个数采员，关系天然是多对多，不应塞进单一 workspace_id。

边界清楚

身份状态与 Workspace 归属分开。账号 code 从一个 Workspace 的 admins/members 移除，只撤销该 Workspace 的访问。

锁定决策

问题决定理由
是否新增关联表否Workspace 已保存 admins/members；重复建表会产生两个事实来源。
是否复制 collector否避免 JWT 身份歧义、资料重复和跨 Workspace 审计分裂。
JWT 是否携带 Workspace否JWT 表达身份；Workspace 权限必须按数据库当前关系实时判断。
数采员是否选择 Workspace否列表聚合其所有 Workspace 中与本人相关的资源。
是否实现通用角色系统否当前只需要“属于/不属于”，Hilbert admin/member 不映射为 Keystone RBAC。
是否设计历史迁移否main-v2 只做新部署，直接修改初始 schema 与实现。
02

现状问题

当前 data_collectors.organization_id 实际承载单个 Workspace ID，同时活动 operator_id 全局唯一。同步同一个 Hilbert account 到第二个 Workspace 时，只能覆盖原 Workspace 或因 current workstation 冲突而跳过。

Current model

data_collectors
  operator_id = alice       UNIQUE
  organization_id = 10     only one workspace

Hilbert reality
  alice -> workspace 10
  alice -> workspace 20

覆盖风险

按 operator_id upsert 会让后同步的 Workspace 覆盖先同步的 Workspace，结果依赖同步顺序。

授权缺口

登录只查一条 collector，JWT 只携带该行 ID，无法表达同一身份在多个 Workspace 中的访问关系。

Hilbert 的处理方式

Hilbert 保留全局 account，并在 Workspace 的 admins_str/members_str 中保存 account code。Keystone 对齐这一所有权模型，但不继续使用 hash-wrapped 字符串：main-v2 将其改成结构化 JSON 数组，并作为唯一访问事实来源。

03

目标领域模型

可编辑源文件：keystone-multi-workspace-collector-membership.drawio

data_collectors

Keystone 内部的全局数采员身份。由 Hilbert account code 唯一定位，保存展示名称、全局启停状态、登录时间和身份元数据。

workspaces.admins/members

保存 Hilbert account code 数组，是 Workspace 归属和访问判断的唯一事实来源，不再派生第二张关系表。

workstations

继续引用全局 data_collector_id，同时显式携带 workspace_id。当前绑定唯一性按 collector + workspace 计算。

tasks / resources

资源自身携带 Workspace。授权时从资源推导 Workspace，再检查对应 admins/members；客户端不提交“当前 Workspace”状态。

04

数据库设计

全局数采员身份

CREATE TABLE data_collectors (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    operator_id VARCHAR(100) NOT NULL,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255),
    certification VARCHAR(100),
    status ENUM('active', 'inactive', 'on_leave') NOT NULL DEFAULT 'active',
    metadata JSON,
    last_login_at TIMESTAMP NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP,
    deleted_at TIMESTAMP NULL,

    _operator_unique VARCHAR(200) GENERATED ALWAYS AS (
        CONCAT(IFNULL(operator_id, ''), '|', IFNULL(deleted_at, ''))
    ) STORED,
    UNIQUE INDEX idx_operator_del (_operator_unique),
    INDEX idx_collector_status (status),
    INDEX idx_collector_deleted (deleted_at)
);
data_collectors 删除 organization_id/workspace_id。operator_id 继续作为 Keystone 与 Hilbert account code、dc_plan.operator 的业务匹配键。

Workspace 访问关系

CREATE TABLE workspaces (
    id BIGINT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    source ENUM('default', 'hilbert') NOT NULL,
    admins JSON NOT NULL,
    members JSON NOT NULL,
    last_synced_at TIMESTAMP NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP,
    deleted_at TIMESTAMP NULL
);
  • 删除旧的 admins_str/members_str hash-wrapped 字符串，API 继续返回字符串数组。
  • 数组元素统一 trim、drop-empty、dedupe，使用标准 JSON parser，不进行字符串模糊匹配。
  • Hilbert Workspace 的 admins/members 只由同步更新；Keystone 管理端只读。
  • source=default 的本地 Workspace 可以通过 Keystone API 管理 admins/members。
  • 账号 code 从数组移除即撤销访问；全局 collector 保留，避免破坏任务和工位历史引用。

工位当前绑定

workstations
  workspace_id BIGINT NOT NULL
  data_collector_id BIGINT NOT NULL

_current_collector_workspace_unique =
  IF(is_current AND deleted_at IS NULL,
     CONCAT(data_collector_id, '|', workspace_id),
     NULL)

UNIQUE(_current_collector_workspace_unique)

同一数采员可以在 Workspace 10 和 Workspace 20 各有一条 current workstation；同一 Workspace 内仍只能有一条。Robot 的 current 唯一约束保持不变。

05

Hilbert 同步语义

读取本轮全部 Hilbert Workspace snapshot
合并每个 Workspace 的 admins + members，按 code 去重
按 code 查询 account，并在本轮内缓存
原子更新 Workspace JSON 访问快照
按 account code upsert 全局 collector

同步算法

validate all workspace snapshots

transaction:
    for workspace in snapshots:
        admins = normalize(workspace.admins)
        members = normalize(workspace.members)
        upsert workspaces(
            id,
            admins = JSON(admins),
            members = JSON(members),
            source = 'hilbert'
        )
commit

codes = union of every workspace admins + members
accounts = query accounts by code with run-level cache

for account in successful account queries:
    upsert global data_collectors by operator_id

report account query failures without reverting workspace snapshot
场景行为安全结果
同一 code 出现在多个 Workspace各 Workspace JSON 保留该 code，collector 全局只 upsert 一次一个身份，多 Workspace 访问
同一 code 同时是 admin 和 member两个数组分别保留语义，访问判断取并集不建立 Keystone RBAC
成员从 Hilbert Workspace 移除下一次完整 Workspace snapshot 直接覆盖 admins/members访问立即撤销
账号查询部分失败Workspace 快照仍按 Hilbert 更新；失败账号不创建或更新 collector已有 collector 按最新关系授权，新账号暂不能登录
collector 不再属于任何 Workspace保留 collector 身份，但登录准入失败历史外键稳定，无资源访问
Device 同步失败不回滚已成功的 Workspace snapshot访问关系与设备投影故障隔离
admins/members 是授权数据。Workspace 列表通过整批校验后才能提交；一旦完整 snapshot 成功，必须覆盖旧数组，使 Hilbert 已移除的账号立即失权。
06

认证与实时授权

JWT 只表达身份

{
  "collector_id": 9,
  "operator_id": "alice",
  "role": "data_collector"
}

JWT 不包含 workspace_id 或 Workspace 列表。关系可能在 token 有效期内变化，所有 Workspace 授权必须查询当前数据库。

登录准入

Hilbert account/login succeeds
  -> find active data_collectors by account.code
  -> require account.code in any active workspace admins/members
  -> issue Keystone JWT
  • Hilbert 负责验证账号密码与账号策略。
  • Keystone collector 必须存在且全局状态为 active。
  • account code 必须至少出现在一个有效 Workspace 的 admins/members，否则返回 403 collector has no accessible workspace。
  • 登录只更新全局 collector 的名称与 last_login_at，不修改工位状态。

授权原语

CanCollectorAccessWorkspace(operatorID, workspaceID):
    workspace = load workspace by ID
    return contains(workspace.admins, operatorID)
        OR contains(workspace.members, operatorID)

ListAccessibleWorkspaceIDs(operatorID):
    load active workspace id + admins + members
    parse JSON arrays with the standard parser
    return IDs whose arrays contain operatorID

列表资源

先计算可访问 Workspace ID，再限制查询范围，并继续叠加“分配给本人”的业务条件。

单个资源

先读取资源自身的 workspace_id，再调用授权原语；不信任客户端提交的 Workspace。

撤权

code 从 admins/members 移除后，下一次请求立即返回 403，不等待重新登录。

admins/members 只提供 Workspace 边界授权，不代表数采员能看到 Workspace 中所有人的数据。任务、Episode、工位等仍要保留 collector ownership 条件。
07

任务与工位行为

数采计划生成任务

require CanCollectorAccessWorkspace(
    dc_plan.operator,
    dc_plan.workspace_id
)

collector = SELECT *
FROM data_collectors
WHERE operator_id = dc_plan.operator
  AND status = 'active'
  AND deleted_at IS NULL

先用计划 Workspace 的 admins/members 验证 operator，再解析全局 collector。同一 operator 在多个 Workspace 中始终得到同一个 collector ID。

当前工位解析

current workstation =
  data_collector_id = collector.id
  AND workspace_id = task.workspace_id
  AND is_current = TRUE
  AND deleted_at IS NULL
约束规则
创建 current workstationcollector 的 operator code 必须出现在目标 Workspace admins/members。
Robot 一致性robot.workspace_id == workstation.workspace_id。
计划一致性dc_plan.workspace_id == robot.workspace_id == workstation.workspace_id。
多 Workspace 并存同一 collector 每个 Workspace 可有一条 current workstation。
plan-specific workstation继续允许 is_current=false 的历史/计划专用绑定，不受 current 唯一约束影响。
code 被移出 Workspace禁止新建和使用该 Workspace 的 current workstation；已有行保留用于历史引用。
08

API 与 Synapse 体验

管理员端

  • 管理员继续先选择 Workspace，再管理该 Workspace 的设备、数采员、工位和计划。
  • GET /data_collectors?workspace_id=... 读取 Workspace admins/members，再按 operator code 返回全局 collector。
  • Hilbert Workspace 的成员关系只读；新增和移除必须回到 Hilbert，下一次同步后生效。
  • default 本地 Workspace 可以通过 Keystone API 向 members 数组添加或移除 operator code。
  • 全局 collector 的软删除是独立身份操作，不隐式改写任何 Workspace 数组。

数采员端

不增加 Workspace selector

登录后仍进入 /operator/control。前端不保存 selectedWorkspaceId，也不要求数采员理解 Workspace 层级。

聚合本人相关资源

任务、工位、Episode 和统计自动覆盖该 collector 在所有有效 Workspace 中的本人数据。

  • 重名任务、设备或工位旁可以显示 Workspace 名称用于消歧，但不提供切换控件。
  • 操作任务时，Workspace 从 task/robot/workstation 资源本身推导。
  • Collector API 不接受前端用任意 workspace_id 扩大查询范围；后端始终按 admins/members 计算可访问边界。

  • 不把 Hilbert admin/member 映射为 Keystone 管理角色。
  • 不建设通用用户、组织、角色和权限平台。

关键测试矩阵

数据与同步

  • 一个 code 同时属于两个 Workspace。
  • admin/member 重复 code 去重。
  • 完整 snapshot 覆盖已移除账号。
  • 账号查询失败不回滚已验证的 Workspace 快照。
  • default Workspace 数组不被 Hilbert 同步修改。

认证与授权

  • code 出现在多个 Workspace 时只签发一个 collector JWT。
  • code 不在任何 Workspace 时登录返回 403。
  • 从一个 Workspace 数组移除后仅对应 Workspace 失权。
  • 伪造 workspace_id 不能扩大访问范围。
  • 全局 inactive collector 在所有 Workspace 失权。

任务与工位

  • 同一 collector 在两个 Workspace 各有 current workstation。
  • 任务只使用同 Workspace 工位。
  • Robot/collector Workspace 不一致时拒绝绑定。
  • plan-specific 非 current 工位继续允许。

Synapse

  • 登录后不出现 Workspace 选择页。
  • 聚合列表包含两个 Workspace 的本人任务。
  • 重名资源有 Workspace 消歧信息。
  • /auth/me.workstations[] 空、单条、多条均正常。

验收口径

使用同一个 Hilbert 账号加入两个 Workspace：同步后 Keystone 只有一个 collector，两个 Workspace 的 admins/members 分别包含该 code；登录一次即可看到两个 Workspace 中分配给本人的任务；执行任一任务时只使用任务所属 Workspace 的工位；从其中一个 Workspace 移除该 code 后，该 Workspace 资源立即不可访问，另一个 Workspace 不受影响。

风险与约束

风险控制措施
可访问 Workspace 计算需要解析 JSON通过统一 repository 和标准 JSON parser 实现；Workspace 规模扩大后再评估 MySQL JSON 查询或派生索引。
同步失败造成权限快照不完整先完整校验 Workspace 列表，再在单事务中原子覆盖全部 Hilbert Workspace 数组。
访问数组与资源 Workspace 串线Station、task generation 和所有写操作统一验证 Workspace 一致性。
前端误把 Workspace access 当作数据可见性后端同时执行 Workspace 授权与 collector ownership 过滤。
用户在多个 Workspace 有多个工位/auth/me 返回数组；任务执行按 task Workspace 精确选择。
Hilbert account code 变化当前契约继续以 code 作为登录和计划 operator 匹配键；同时在 metadata 保留 Hilbert account ID 便于诊断。
