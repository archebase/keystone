面向 SDK 使用者：从设备初始化到文件上传完成，你需要调用哪些公开接口、按什么顺序调用，以及失败后如何恢复。

核心判断：App 只编排 SDK 公共 API。认证交换、STS、分片上传、重试和 Keystone 完成确认均由 SDK 内部处理。

00

先确定调用边界

DO NOT BYPASS THE SDK

SDK 使用者需要准备本地路径、可信配置、设备初始化材料、待上传文件和任务上下文。其余上传协议由 SDK 负责。

App 需要调用

DataGatewayClient、ArchebaseDeviceInitializer、UploadRequest 以及恢复和取消相关公开方法。

App 不应该调用

不要直接调用 Keystone 的 AuthService、DataGatewayService，也不要自行申请 STS、拼接 object key 或直接编排 TOS multipart。

APP提供文件与任务上下文
SDK认证、持久化、编排
KEYSTONE授权上传与完成业务
OBJECT STORE接收文件字节
APP接收 UploadResult
文件字节不会经过 Keystone。App 调用 SDK 后，SDK 使用 Keystone 签发的临时凭证直传对象存储，并在数据上传完成后自动回调 Keystone 完成业务确认。
01

你需要知道的接口

PUBLIC SURFACE

正常接入只需要下面 9 个入口。前 5 个完成首次上传，后 4 个处理生命周期和异常。

公开接口 何时调用 调用结果
DataGatewayClient.initialize 首次使用 SDK 端点前 校验并原子写入 archebase-endpoints.json。
ArchebaseDeviceInitializer.initDevice 设备首次初始化 向 Keystone 初始化设备；API Key 进入 Keychain，tags 写入配置。
DataGatewayClient.fromArchebaseConfig 初始化完成后、App 启动时 创建可复用的 DataGatewayClient actor。
UploadRequest.init 每次新上传前 封装文件 URL、Keystone 任务上下文和业务标签。
client.upload 不需要实时进度 UI 等待整条上传链路完成并返回 UploadResult。
client.uploadEvents 需要阶段和分片进度 UI 返回同一次新上传的 AsyncThrowingStream<UploadEvent, Error>。
client.listPendingUploads App 启动或回到前台 列出本机仍可恢复的 active 快照。
client.resumeUpload 用户选择恢复任务 校验源文件并恢复分片上传或补齐最终确认。
client.abortUpload 用户明确放弃上传 将 Keystone 逻辑上传标记为 aborted，并清理本地快照。
deleteLocalSnapshot 是支持和异常清理接口。它只删本地快照，不更新 Keystone 状态，普通“取消上传”按钮不应调用它。
02

初始化与创建客户端

ONE-TIME BOOTSTRAP
1计算本地路径全部放在 App 私有的 Application Support 目录。
2写入 endpoints配置必须来自可信渠道，不要硬编码生产密钥。
3初始化设备只在本机没有设备配置时调用。
4创建 client创建后在 App 服务层复用，不必每次上传重新创建。

2.1 计算三个本地路径

Swift / Local paths
import DataGatewayClient
import DGWControlPlane
import DGWStore
import Foundation

let supportRoot = FileManager.default.urls(
    for: .applicationSupportDirectory,
    in: .userDomainMask
)[0]

let archebaseRoot = supportRoot.appendingPathComponent(
    "Archebase",
    isDirectory: true
)

let endpointsURL = archebaseRoot.appendingPathComponent(
    "archebase-endpoints.json"
)
let configURL = archebaseRoot.appendingPathComponent(
    "archebase-config.json"
)
let persistRootURL = archebaseRoot.appendingPathComponent(
    "Uploads",
    isDirectory: true
)

2.2 写入可信 endpoint JSON

Call 01 / DataGatewayClient.initialize
try DataGatewayClient.initialize(
    endpointsJSON: endpointsJSONStringFromTrustedChannel,
    endpointsURL: endpointsURL
)

同一份配置可重复调用并幂等成功。如果文件已存在但内容不同，SDK 会抛出 endpointsAlreadyInitialized，避免 App 静默切换服务端。

2.3 首次初始化设备

Call 02 / ArchebaseDeviceInitializer.initDevice
let initializer = try ArchebaseDeviceInitializer(
    config: DeviceInitClientConfig(
        configURL: configURL,
        endpointsURL: endpointsURL
    )
)

let deviceConfig = try await initializer.initDevice(
    deviceName: deviceNameFromTrustedConfig,
    deviceAuthToken: deviceAuthTokenFromTrustedConfig
)

print(deviceConfig.tags)

initDevice 只用于首次初始化。若本地已有配置，SDK 抛出 alreadyInitialized；不要因为普通上传失败而自动调用 reinitDevice。

2.4 创建并复用上传客户端

Call 03 / DataGatewayClient.fromArchebaseConfig
let client = try await DataGatewayClient.fromArchebaseConfig(
    configURL: configURL,
    persistRootURL: persistRootURL,
    endpointsURL: endpointsURL,
    observability: .disabled
)
  • API Key 由 SDK 放入 Keychain，不写入日志或用户可导出文件。
  • archebase-config.json 中的设备 tags 会自动合并到每次上传。
  • 如果抛出 notInitialized，进入设备初始化流程。
  • 如果抛出 endpointsNotInitialized，先写入 endpoint JSON。
03

构造请求并发起上传

NEW UPLOAD

每次上传只需构造一个 UploadRequest。最容易出错的是任务上下文，而不是文件传输本身。

3.1 Keystone 必需的任务字段

字段 放入位置 要求
capture_id clientHints + rawTags 两处必须使用同一个值，用于标识采集并组成服务端对象路径。
task_id clientHints + rawTags 必须对应 Keystone 中已存在且可上传的 Task。
dc_plan_id clientHints + rawTags 正整数的十进制字符串，并且必须与 Task 所属计划一致。
workspace_id rawTags 必须与设备身份一致。设备初始化返回的配置 tags 通常会自动提供该值。
不要自行传入或覆盖 device_id 来切换身份。Keystone 以认证后的设备 principal 为准，显式传入不一致的身份字段会被拒绝。

3.2 构造 UploadRequest

Call 04 / UploadRequest
let taskContext = [
    "capture_id": captureID,
    "task_id": taskID,
    "dc_plan_id": String(dcPlanID)
]

let request = UploadRequest(
    fileURL: fileURL,
    clientHints: taskContext,
    rawTags: taskContext.merging(
        [
            "workspace_id": String(workspaceID),
            "scene": "inspection"
        ],
        uniquingKeysWith: { _, new in new }
    ),
    displayName: fileURL.lastPathComponent
)

如果客户端由 fromArchebaseConfig 创建，而且配置 tags 已含相同的 workspace_id，可以不在单次请求中重复传入。重复传入时值必须完全相同，否则 SDK 在创建远端上传前抛出 rawTagConflict。

3.3 不需要进度 UI：调用 upload

Call 05A / client.upload
let result = try await client.upload(request)

print(result.logicalUploadID)
print(result.objectKey)
print(result.fileSize)
print(result.ossObjectETag)

upload 返回时，文件数据已经写入对象存储，并且 Keystone 的 CompleteUpload 业务确认已经成功。只完成对象存储上传但未完成 Keystone 确认，不会返回成功结果。

04

需要进度 UI 时

ASYNC EVENT STREAM

uploadEvents 会启动一次新的上传。它不是对另一个 upload 调用的旁路监听器，因此两者只能二选一。

Call 05B / client.uploadEvents
var newlySentBytes: UInt64 = 0
var finalResult: UploadResult?

for try await event in await client.uploadEvents(request) {
    switch event {
    case .preparing:
        await updateStatus("正在检查文件")

    case .authenticating:
        await updateStatus("正在认证设备")

    case .creatingLogicalUpload:
        await updateStatus("正在创建上传任务")

    case .initiatingMultipart:
        await updateStatus("正在初始化分片上传")

    case .uploadingPart(_, let sentBytes, let totalBytes):
        newlySentBytes += sentBytes
        let progress = min(
            Double(newlySentBytes) / Double(totalBytes),
            1
        )
        await updateProgress(progress)

    case .refreshingCredentials:
        await updateStatus("正在刷新上传凭证")

    case .reconcilingRemoteParts:
        await updateStatus("正在核对已上传分片")

    case .completingMultipart:
        await updateStatus("正在完成文件上传")

    case .completingBusinessUpload:
        await updateStatus("正在确认业务结果")

    case .completed(let result):
        finalResult = result
        await updateProgress(1)

    case .resuming:
        await updateStatus("正在恢复上传")
    }
}
uploadingPart.sentBytes 表示当前事件新发送的分片字节数，不是累计值。恢复上传时，它也不包含上一次进程已经传完的字节，因此 UI 应明确区分“本次发送进度”和“历史总进度”。

在 SwiftUI 或 UIKit 中更新界面时，把状态更新切换到 MainActor。不要在事件循环中执行耗时同步工作，否则会拖慢事件消费和 UI 响应。

05

启动恢复、取消与清理

LIFECYCLE CONTROL

5.1 App 启动后检查待恢复任务

Call 06 / client.listPendingUploads
let pendingUploads = try await client.listPendingUploads()

for pending in pendingUploads {
    print(pending.logicalUploadID)
    print(pending.fileURL)
    print(pending.fileSize)
    print(pending.phase)
}

SDK 不使用 iOS URLSession background transfer。App 被挂起或终止后，不要假设上传仍在后台运行；回到前台或重启后应重新创建 client 并检查 pending uploads。

5.2 恢复用户选择的任务

Call 07 / client.resumeUpload
let result = try await client.resumeUpload(
    logicalUploadID: pending.logicalUploadID
)

恢复前 SDK 会检查原始文件仍然存在、大小未变化、修改时间和首个 1 MiB 指纹匹配。文件被移动、删除或改写时会抛出 resumeNotPossible。

5.3 用户明确放弃上传

Call 08 / client.abortUpload
try await client.abortUpload(
    logicalUploadID: pending.logicalUploadID
)

该方法同步更新 Keystone 逻辑状态并删除本地快照。当前实现不会立即删除已经写入的对象，也不会直接取消对象存储 multipart；残留资源由服务端生命周期策略或清理任务处理。

5.4 仅删除损坏的本地记录

Support only / client.deleteLocalSnapshot
try await client.deleteLocalSnapshot(
    logicalUploadID: pending.logicalUploadID
)
这个方法不会通知 Keystone。只有用户明确选择“仅从本机移除记录”或支持人员要求清理本地损坏状态时才使用。
06

错误处理决策表

FAILURE ROUTING
错误 App 应采取的动作
notInitialized进入设备初始化界面，不要直接重试上传。
alreadyInitialized跳过初始化，直接调用 fromArchebaseConfig 创建 client。
endpointsNotInitialized从可信渠道获取 endpoint JSON，调用 DataGatewayClient.initialize。
endpointsAlreadyInitialized停止自动切换环境，交给明确的运维流程处理。
rawTagConflict修正单次 rawTags，确保与设备配置 tags 使用相同值。
invalidLocalFile / zeroByteFile让用户重新选择有效且非空的文件。
authenticationFailed停止自动重试；提示检查设备状态或联系管理员，不要自动 reinit。
gatewayFailed记录非敏感的 detailCode，按业务错误提示用户。
ossFailed / retryExhausted提示网络或对象存储暂时不可用，保留快照并允许稍后恢复。
resumeNotPossible提供重新上传、调用 abortUpload 或支持性本地清理入口。
uploadRestartExceeded停止恢复循环，提示重新发起一次新上传。
Recommended error boundary
do {
    let result = try await client.upload(request)
    await showCompleted(result)
} catch let error as DataGatewayClientError {
    switch error {
    case .notInitialized:
        await showDeviceInitialization()
    case .rawTagConflict(let key):
        await showMetadataError(key: key)
    case .invalidLocalFile, .zeroByteFile:
        await askUserToSelectFileAgain()
    case .resumeNotPossible:
        await showRestartOrAbortActions()
    case .authenticationFailed:
        await showContactAdministrator()
    case .gatewayFailed(_, let detailCode, _):
        await showGatewayError(code: detailCode)
    case .ossFailed, .retryExhausted:
        await showResumeLater()
    default:
        await showGenericUploadFailure()
    }
}

日志中可以记录操作名、阶段、logicalUploadID、非敏感错误码和时间。不要记录 API Key、device auth token、Bearer JWT、STS secret、带签名 URL 或完整配置字符串。

07

App 侧完整封装

REFERENCE IMPLEMENTATION

建议在 App 内封装一个 actor，集中管理路径、client 生命周期、上传、恢复和取消。UI 层只传业务参数，不直接接触配置文件和凭证。

GatewayUploadService.swift
import DataGatewayClient
import DGWControlPlane
import DGWStore
import Foundation

actor GatewayUploadService {
    private let endpointsURL: URL
    private let configURL: URL
    private let persistRootURL: URL
    private var client: DataGatewayClient?

    init() {
        let supportRoot = FileManager.default.urls(
            for: .applicationSupportDirectory,
            in: .userDomainMask
        )[0]
        let root = supportRoot.appendingPathComponent(
            "Archebase",
            isDirectory: true
        )

        self.endpointsURL = root.appendingPathComponent(
            "archebase-endpoints.json"
        )
        self.configURL = root.appendingPathComponent(
            "archebase-config.json"
        )
        self.persistRootURL = root.appendingPathComponent(
            "Uploads",
            isDirectory: true
        )
    }

    func initializeEndpoints(json: String) throws {
        try DataGatewayClient.initialize(
            endpointsJSON: json,
            endpointsURL: self.endpointsURL
        )
    }

    func initializeDevice(
        deviceName: String,
        deviceAuthToken: String
    ) async throws {
        let initializer = try ArchebaseDeviceInitializer(
            config: DeviceInitClientConfig(
                configURL: self.configURL,
                endpointsURL: self.endpointsURL
            )
        )

        _ = try await initializer.initDevice(
            deviceName: deviceName,
            deviceAuthToken: deviceAuthToken
        )
        self.client = try await self.makeClient()
    }

    func loadClient() async throws -> DataGatewayClient {
        if let client = self.client {
            return client
        }
        let client = try await self.makeClient()
        self.client = client
        return client
    }

    func upload(
        fileURL: URL,
        captureID: String,
        taskID: String,
        dcPlanID: Int64,
        workspaceID: Int64,
        extraTags: [String: String] = [:]
    ) async throws -> UploadResult {
        let context = [
            "capture_id": captureID,
            "task_id": taskID,
            "dc_plan_id": String(dcPlanID)
        ]
        let requiredTags = context.merging(
            ["workspace_id": String(workspaceID)],
            uniquingKeysWith: { _, new in new }
        )
        let rawTags = requiredTags.merging(
            extraTags,
            uniquingKeysWith: { current, _ in current }
        )

        let request = UploadRequest(
            fileURL: fileURL,
            clientHints: context,
            rawTags: rawTags,
            displayName: fileURL.lastPathComponent
        )

        let client = try await self.loadClient()
        return try await client.upload(request)
    }

    func pendingUploads() async throws -> [PendingUploadInfo] {
        let client = try await self.loadClient()
        return try await client.listPendingUploads()
    }

    func resume(logicalUploadID: String) async throws -> UploadResult {
        let client = try await self.loadClient()
        return try await client.resumeUpload(
            logicalUploadID: logicalUploadID
        )
    }

    func abort(logicalUploadID: String) async throws {
        let client = try await self.loadClient()
        try await client.abortUpload(
            logicalUploadID: logicalUploadID
        )
    }

    private func makeClient() async throws -> DataGatewayClient {
        try await DataGatewayClient.fromArchebaseConfig(
            configURL: self.configURL,
            persistRootURL: self.persistRootURL,
            endpointsURL: self.endpointsURL
        )
    }
}

接入完成的验收标准

  • 首次安装可写入 endpoints、初始化设备并创建 client。
  • 合法 Task 上下文可以完成小文件和 multipart 大文件上传。
  • UI 使用 uploadEvents 时不会重复调用 upload。
  • App 重启后可列出 pending uploads，并允许恢复或取消。
  • 源文件变化时能正确提示无法恢复，不进入无限重试。
  • 日志和埋点不包含 API Key、JWT、STS 或完整可信配置。
最小成功路径只有五个动作：写入 endpoints → 初始化设备 → 创建 client → 构造 UploadRequest → 调用 upload。进度、恢复和取消是在这条主线之上的生命周期能力。
