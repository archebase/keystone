What changed

你会看到这些新能力

这次更新不改变 Episode 的基本概念，而是在原始 MCAP 旁增加一份可追踪的“双目拆分派生数据”。

01

数据明细页新增“双目拆分”

可以执行、取消、重试、查看日志，并查看这一条数据的处理和自动质检状态。

02

派生结果可预览、下载

成功后可以看到文件大小、时长、左右图像、IMU、跳过消息等统计。

03

支持批量双目拆分

按当前筛选或勾选范围预览任务，确认预计提交和跳过数量后再执行。

04

处理成功后自动质检

不需要手动发起第一次质检；质检不通过时，可单独重新质检，无需重新拆分。

05

同步仍由管理员确认

自动质检通过后才出现“同步派生文件到云”，系统不会自动同步。

06

任务离开页面也会继续

处理、验证、质检与失败恢复由服务端记录；关闭页面不会取消已经提交的任务。

Single episode

处理一条数据

进入管理员的数据明细页，找到新的“派生处理 / 双目拆分”区域。

  1. 点击“执行双目拆分”。系统会先检查原始 MCAP 是否可处理，并进入排队状态。
  2. 等待状态依次经过排队、提交、等待调度、处理中、验证产物。需要时可查看日志；活跃任务可以取消。
  3. 处理成功后，系统会自动执行派生数据质检。页面会显示左图、右图、IMU 等结果统计。
  4. 质检通过后，可先预览或下载派生 MCAP，再由管理员点击“同步派生文件到云”。
  5. 若云同步失败，可重试同一份派生文件；已经选定的同步来源不会改变。

关键变化：“处理成功”和“已经同步”是两件事。自动质检通过后，派生文件仍然只保存在数据存储中，必须由管理员点击同步按钮才会发布到云端。

Status guide

页面状态怎么理解

页面状态表示什么你可以做什么
排队中 / 提交中任务正在等待或提交给计算服务。等待，或在允许时取消。
等待调度 / 处理中作业已经创建，正在准备或执行脚本。查看日志，必要时取消。
验证产物脚本已结束，系统正在检查输出文件和统计是否可信。等待验证完成。
处理成功派生 MCAP 已验证并保存，随后进入自动质检。预览、下载；质检通过后同步。
处理失败脚本、输入、输出验证或运行环境出现问题。查看说明和日志；清理阶段结束后重试。
已取消本次 generation 已停止，不会发布为成功结果。清理阶段结束后可重新执行。
自动质检通过派生数据满足当前双目拆分质量规则。管理员可点击同步派生文件到云。
自动质检不通过处理结果仍保留，但暂时不能同步。查看质检说明，并点击重新质检。

One official cloud representation

原始文件和派生文件只能同步一种

原始 MCAP 和双目拆分 MCAP 可以同时保存在数据存储中，用于下载、检查和审计；但对于 Hilbert，一个 Episode 始终只对应一条正式数据。

选择原始 MCAP 同步

  • 一旦原始文件开始同步，该 Episode 的正式来源被锁定为原始文件。
  • 之后不能再执行或重试双目拆分。
  • 同步失败也只能继续重试同一份原始文件。

选择双目拆分 MCAP 同步

  • 双目拆分开始或成功后，原始文件的同步入口会被锁定。
  • 派生质检通过后，由管理员确认同步派生文件。
  • 同步失败也只能继续重试同一份派生文件。

不可切换：同步来源是业务选择，不是临时状态。一旦原始或派生来源被正式认领，不能清空后改传另一份文件。

Bulk processing

批量处理大量数据

在“数据操作”页面使用“批量双目拆分”。系统会为每个符合条件的 Episode 独立创建任务；默认每次只运行 1 个，其余任务排队等待，不会把整批数据塞进同一个长时间运行的 Pod。管理员可以在“系统设置”中调整这个全局上限。

  1. 先设置筛选条件，或明确勾选需要处理的数据。
  2. 点击“批量双目拆分”，查看本次选中、预计提交、预计跳过及跳过原因。
  3. 确认后点击“开始拆分”。可以在进度面板中查看派生成功、处理失败和质检不通过数量。
  4. 点击“查看明细”，逐条查看准入结果、原因、generation、处理结果和自动质检结果。
常见跳过原因含义
已派生成功这条数据已经有成功结果，不会重复处理。
云发布来源已锁定该 Episode 已选择原始文件作为正式同步来源。
正在拆分或排队中已有活跃任务，本批次不会再创建一个。
上次作业清理中上次失败或取消的作业仍在完成 API 清理阶段。
源 MCAP 不可用系统无法从当前存储信息定位可处理的 TOS 源文件。

批量预览是提交前的估算。真正轮到某条数据准入时，系统会再次检查它是否仍然符合条件，因此最终数量可能与预览略有差异。

Admin settings

管理员新增“系统设置”

管理后台侧边栏新增独立的系统设置页面。第一期提供“双目拆分”分区，以后其他系统参数可以继续增加新的设置分区。

页面可以配置

  • 任意可由集群拉取的完整镜像地址；Keystone 不限制仓库。
  • 必须使用不可变的 @sha256:... digest。
  • 最大同时处理数，允许范围为 1～100，默认值为 1。
  • 可以查看当前 revision、配置来源、修改人和历史记录。

页面不能配置

  • 镜像仓库密码或 Token。
  • Kubernetes 的 imagePullSecret。
  • 脚本命令、CPU、内存或任意用户参数。

并发调整如何生效：单条操作和全部批次共享同一个上限。调高后系统会继续从队列补充作业；调低不会强制停止已经运行的作业，而是在活跃数量降到新上限前不再启动新的作业。

部署配置已经收敛：本功能只新增 Orbit 地址和派生输出前缀两个 Keystone 环境变量。配置 Orbit 地址即启用功能；不再单独配置开关、镜像仓库白名单、作业资源、并发或派生 bucket。派生文件固定写入 Keystone 已管理的 TOS bucket，镜像与并发由本页面维护。

如果执行入口提示不可用或请求被拒绝：可能是当前环境未配置 Orbit 地址、镜像尚未配置、源 MCAP 不在受支持的 TOS 存储中，或该 Episode 已经选择了原始文件同步。

Data safety

你的数据会怎样

A

原始 MCAP 不会被覆盖

双目拆分输出使用独立路径。失败、取消或重试也不会修改原始文件。

B

成功结果不会重复生成

一个 Episode 只保留一个当前双目拆分记录；一旦成功，后续批次会自动跳过。

C

失败重试使用新 generation

新一次执行拥有独立作业和输出路径，不会混用上一次失败任务的产物。

D

输出必须先通过验证

系统会检查清单、文件大小、校验值和 MCAP 内容，不能只凭作业显示成功。

E

Hilbert 无需理解派生关系

Hilbert 仍只看到一条普通 rawData；原始/派生选择完全由 Keystone 管理。

F

页面关闭不丢任务

任务状态、批次成员、处理结果和同步来源均持久化保存，可在服务恢复后继续。
