01

核心范围：复用传输，新增业务落点

Keystone 现有设备上传链路已经覆盖设备初始化、设备凭证交换、STS 临时授权、TOS 分片上传、断点恢复与上传完成通知。本设计不复制这些能力，只在上传意图解析处增加分流。

标定数据不是 Episode：不创建虚假 DC Plan，不创建虚假 Task，也不把 episodes.task_id 改成可空。

本次要完成

  • 保留原任务上传的全部接口和业务行为。
  • 让设备凭证可以上传不绑定数采员、计划和任务的标定 MCAP。
  • 支持一轮标定持续产生多条 Capture，直到任意一条标定成功。
  • 让 Ego Portal 在标定上传中提供 camera_serial，并在同一 Session 内保持不变。
  • 让 Ego Portal 使用持久 Device Token 或 API Key 换取的临时 Device JWT 查询本设备的标定 Session 状态。
  • 每条 MCAP 上传完成后自动排队：Keystone 只提交一个 Orbit 标定 Job；Job 内先把 DECXIN 原始 MCAP 拆成双目图像并提取 IMU，再运行标定并把一对一结果 JSON 写入 TOS。
  • 首条成功后停止新任务，并持久化取消同一 Session 中仍在运行的 Orbit Job。

本次不做

  • 不修改 protobuf。
  • 不发布新版公共上传 SDK。
  • 不改变 Episode、Task 或 QA 接口。
  • 不把 Ego 本地账号映射为 Keystone 数采员。
  • 不要求管理员逐条点击启动标定。

一条原始 MCAP 对应一条 calibration_capture：Keystone 把上传完成且身份已冻结的 capture.mcap 只读挂载给一个标定 Job。Job 在临时工作目录中拆分 DECXIN 双目图像并提取 IMU，不生成视频流；预处理满足双目完整性和非空 IMU 质量门后，立即在同一 Job 中运行标定并产生一份结果 JSON。一轮 calibration_session 固定一个 camera_serial，可以包含多条 Capture。录制与服务端处理并行，Ego Portal 持续上传并使用 Device Token 轮询状态，直到第一条成功结果出现。

04

旧接口的兼容扩展

上传类型判定

client_hints["upload_kind"] 服务端行为
缺失或空字符串 按旧的 task_episode 处理。
task_episode 要求并校验原有 task_id、dc_plan_id、workspace 和 workstation 绑定。
calibration_capture 进入新标定分支，要求 camera_serial，不要求 Task、DC Plan 或 workstation。
其他值 返回 gRPC InvalidArgument。

标定上传 hints

CreateLogicalUpload.client_hints 
{
  "upload_kind": "calibration_capture",
  "camera_serial": "CAMERA-SN-20260805-0001",
  "calibration_session_id": "7f9af590-75c2-47ad-b6e0-76ebf05c44f7",
  "capture_id": "92cd6f2f-d131-4bf0-9b4a-d96258d09011",
  "attempt_no": "3",
  "checksum_sha256": "64-character-lowercase-hex",
  "source": "ego-portal",
  "local_operator": "local-user"
}

calibration_session_id 和 capture_id 都必须由客户端生成为规范小写 UUIDv4：前者在整轮“持续录制直到首次成功”期间保持不变，后者每条 MCAP 重新生成。camera_serial 由 Ego Portal 提供，Keystone 只做一次首尾空白裁剪；裁剪后必须非空、不超过 255 个 Unicode 字符且不能包含控制字符。值区分大小写，Keystone 在首次创建 Session 时保存规范化后的值，后续 Capture 必须与 Session 中保存的值完全一致。缺失或非法值在 Create 阶段返回 gRPC InvalidArgument，因此不会签发 STS。camera_serial 只绑定当前 Session，不与 Device 建立永久绑定；同一 Device 可以为不同序列号创建不同 Session，不同 Session 也允许重复使用同一序列号。服务端必须从 Device JWT 获取 robot_id、device_id 和 workspace_id；客户端不能指定或覆盖设备和空间身份。

CompleteUpload.raw_tags 
{
  "upload_kind": "calibration_capture",
  "camera_serial": "CAMERA-SN-20260805-0001",
  "calibration_session_id": "7f9af590-75c2-47ad-b6e0-76ebf05c44f7",
  "capture_id": "92cd6f2f-d131-4bf0-9b4a-d96258d09011",
  "attempt_no": "3",
  "checksum_sha256": "64-character-lowercase-hex",
  "duration_sec": "30.0",
  "source": "ego-portal",
  "local_operator": "local-user"
}

CompleteUpload.raw_tags 必须重复提供规范化后的 camera_serial，并与 Create 时保存的 hints 及数据库 Session 值同时一致；缺失、大小写变化或其他变更都返回 gRPC FailedPrecondition。该校验也适用于重复 Complete；重复请求的 camera_serial、对象路径、文件大小、SHA-256 和 duration_sec 语义值必须与首次完成时保存的值一致，否则返回 FailedPrecondition。duration_sec 必须能以数据库的 DECIMAL(12,3) 无损表示，即最大为 999999999.999 秒且精确到毫秒；30.0、30.00 与 30.0000 表示同一个时长，而 30.0004 或 1000000000 返回 InvalidArgument。

服务端生成对象路径

TOS OBJECT KEY 
device-uploads/calibration-captures/{device_id}/{calibration_session_id}/{capture_id}/capture.mcap

标定 Capture 复用 KEYSTONE_DGW_TOS_KEY_PREFIX（默认 device-uploads）及现有 Upload Role 的前缀权限；Keystone 签发的单次 STS Session Policy 仍只允许访问本次生成的精确对象 key，不新增根级 calibration-captures/* 权限。

CompleteUpload 分流

上传类型 完成动作 明确不做
task_episode 创建 Episode、完成 Task、进入 Episode QA。 无变化。
calibration_capture 再次校验 raw tags 中的 camera_serial 与 Session 保存值一致，保存原始 MCAP 元数据并将 Capture 标记为 queued；后台提交一个读取原始 capture.mcap 的标定 Orbit Job，由该 Job 顺序完成预处理和标定。 不创建 Episode、不修改 Task、不进入 Episode QA 或云同步。

首次收到新的 calibration_session_id 时，Keystone 惰性创建状态为 running 的 Session，并保存 camera_serial；每次创建逻辑上传时，创建或恢复对应 Capture。已存在 Session 的 camera_serial 不一致时返回 gRPC FailedPrecondition。并发请求同时首次创建同一 Session 时，数据库冲突方会回滚并重新读取已经落库的 Session，再执行相同的设备归属和序列号校验；因此不同序列号仍稳定返回 FailedPrecondition，不会被泛化为临时数据库错误。

05

新增 REST 接口

这些接口承接异步标定状态和结果，不进入公共上传 SDK，也不要求修改 Data Gateway protobuf。

设备状态查询

GET
/api/v1/device/calibration-sessions/{session_id} 设备鉴权；持久 Device Token 与临时 Device JWT 二选一。
200 RESPONSE 
{
  "session_id": "7f9af590-75c2-47ad-b6e0-76ebf05c44f7",
  "camera_serial": "CAMERA-SN-20260805-0001",
  "status": "succeeded",
  "successful_capture_id": "92cd6f2f-d131-4bf0-9b4a-d96258d09011",
  "capture_count": 4,
  "uploaded_count": 4,
  "processed_count": 3,
  "updated_at": "2026-08-02T10:20:30Z"
}

processed_count 只统计已经产出并通过 Keystone 校验的结果 JSON；仅完成上传、但因 Session 已成功而直接标记为 superseded 的 Capture 不计入。

  • 持久凭证：Device-Authorization: <device_auth_token>。该 Token 是管理员下发并用于初始化的设备凭证。
  • 临时凭证：Authorization: Bearer <device-jwt>。Device JWT 必须由设备 API Key 通过 AuthService.ExchangeCredential 换取；API Key 本身不能直接调用 REST 接口。
  • 两个请求头必须二选一；同时发送返回 400 Bad Request，错误码为 ambiguous_device_credentials。
  • 缺少凭证，或者凭证无效、过期、撤销、issuer/token type 不正确：401 Unauthorized；设备凭证认证数据库暂时不可用：503 Service Unavailable。
  • Session 不存在或不属于当前设备：404 Not Found。
  • Session ID 格式非法：400 Bad Request。

当前 Ego Portal 初始化成功后会删除本地 device_auth_token，因此它接入标定状态查询时可直接复用现有 API Key 换取短期 Device JWT 的流程。仍安全持久化 Device Token 的客户端可以使用 Device-Authorization；两条路径最终解析为同一份包含 robot、device、workspace 和 auth_epoch 的设备身份。

Orbit 标定作业与后续 Synapse 查询

    "size_bytes": 120000,

  },
  "result": {
    "camera_matrix": [],
    "distortion_coefficients": []
  }
}

处理只提交一个 Orbit Job。原始 capture.mcap 以只读 data binding 挂载到 /bindings/input/，输出目录挂载到 /bindings/output/；Job 在容器临时目录中生成仅供本次运行使用的预处理 MCAP，确认双目图像完整且成功提取 IMU 后调用 ArcheBase 标定流水线。标定成功或业务失败都写到 calibration-results/{device_id}/{session_id}/{capture_id}/result.json；JSON 的 source.uri、source.size_bytes 和 source.sha256 必须指向 Keystone 冻结的原始 capture.mcap，并且 camera_serial、processor_image、Capture ID 和 Session ID 必须与冻结的执行上下文一致，否则结果会被拒绝。预处理 MCAP 不作为独立 TOS 产物发布，也不会创建第二个 Orbit Job。

06

数据模型与状态机

calibration_sessions

  • id
  • session_id UNIQUE
  • camera_serial
  • robot_id
  • workspace_id
  • status
  • successful_capture_id
  • created_at / updated_at

calibration_captures

  • capture_id UNIQUE（全局随机 UUIDv4）
  • calibration_session_id
  • workspace_id / attempt_no
  • status
  • mcap_object_key
  • mcap_size_bytes / mcap_sha256
  • duration_sec / local_operator
  • result_json / algorithm_version
  • calibration_error
  • uploaded_at / processing_started_at / processing_finished_at

camera_serial 只存储在 calibration_sessions，不复制到 Capture 表，也不建立全局唯一索引。Capture 查询通过所属 Session 返回相同的 camera_serial。迁移前的历史 Session 保留 NULL 并且仍可查询，状态响应将其表示为空字符串；为避免无法证明相机身份，这类 Session 不允许再创建新的 Capture。

Capture 主状态流

uploading
queued
submitting
pending / running
verifying
succeeded

标定失败的 Capture 进入 failed，但所属 Session 保持 running，Ego 继续录制上传。Session 成功后，尚未提交的 Capture 直接标记为 superseded；已提交或运行的 Capture 持久化取消请求，Orbit 停止后再标记为 superseded。

新 Capture 从 processing_stage=calibration 开始并只创建一个 Orbit Job，该 Job 直接读取上传的原始 capture.mcap。stereo_split 阶段只为升级时已经冻结或运行的历史 Capture 保留：这类任务继续按旧合同验证后再进入标定阶段，避免部署升级中断在途作业；迁移时尚未启动 stereo-split 的 Capture 会安全切换到单 Job 流程。

首条成功原子收敛

提交成功结果时，Keystone 在同一事务中更新 Capture、将 Session 从 running 改为 succeeded、写入 successful_capture_id、淘汰未提交 Capture，并为活跃 Orbit Job 写入可重试的取消请求。只有第一条成功 Capture 能获胜，后续并发结果不能覆盖。
07

安全、幂等与竞态

设备鉴权状态接口

设备状态查询接受 Device-Authorization 中的持久 Device Token，或 Authorization: Bearer 中的短期 Device JWT，并统一解析设备身份及当前 auth_epoch；即使知道 session_id，其他设备也只能得到 404 Not Found。session_id 仍必须使用规范小写 UUIDv4。响应只包含相机序列号、运行状态、计数和成功 Capture ID，不返回对象路径、操作员或其他敏感元数据，并设置 Cache-Control: no-store。

上传幂等

  • 同一设备重复完成相同 capture_id 时，camera_serial、对象路径、文件大小、SHA-256 和 duration_sec 语义值全部一致则返回成功。
  • 任一字段不一致时返回 gRPC FailedPrecondition，禁止静默覆盖。
  • 上传完成自动入队；兼容接口 POST .../process 重复调用也不会创建第二个 Orbit 作业。

Session 成功时的在途请求

请求时机 处理策略
成功后新建上传 CreateLogicalUpload 返回 FailedPrecondition，不再签发 STS。
成功前已开始、成功后完成 允许 CompleteUpload 收口对象，Capture 标记为 superseded。
成功时仍在队列中 不再提交 Orbit，Capture 原子标记为 superseded。
成功时 Orbit 已提交或运行 记录可恢复的取消请求并调用 Orbit Stop；失败按轮询间隔重试，确认停止后标记为 superseded。
Ego 轮询到 succeeded 不再开始下一段；当前录制正常结束，避免损坏 MCAP，但不再排队上传。
08

发布、兼容与验证

客户端 / 服务端组合 结果
旧 Ego + 旧 Keystone 原任务上传正常。
旧 Ego + 新 Keystone 原任务上传正常，行为不变。
新 Ego + 新 Keystone 目标版本：任务上传与携带 camera_serial 的标定上传均正常。
新 Ego + 旧 Keystone 标定上传不受支持，会因缺少任务绑定而失败。
截至本设计对应的代码检查点，Ego Portal 最新远端分支尚未实现标定录制/上传，也不会上传 camera_serial；上表中的“新 Ego”是后续目标版本，不代表当前客户端已经具备该能力。Keystone 必须先上线并保持旧任务上传兼容。

Orbit 标定作业部署配置

KEYSTONE ENV 
KEYSTONE_ORBIT_BASE_URL=http://orbit.archebase-system.svc.cluster.local:8080

标定功能没有单独的启用开关，并使用现有 Orbit 服务地址。上线前在“系统设置 → 设备标定”中保存不可变 @sha256: 标定镜像引用和最大并发；Keystone 冻结该处理配置后提交单个 Job，资源、超时、清理时间、轮询间隔、结果大小和日志上限使用现有安全配置或内置值，不增加标定专用环境变量。生产镜像由 Keystone 的 make calibration-image 生成：Make 通过 SSH 从 robotics-and-ai/archebase_calib 解析指定 ref 的完整 commit SHA，再把该远程仓库作为 BuildKit Git context 构建，因此不读取本地 archebase_calib 目录，也不修改算法仓库。镜像必须接受原始 capture.mcap 合同，并在同一 Job 内完成预处理和标定。

发布顺序不能反转

  1. 先部署数据库迁移和新版 Keystone。
  2. 验证旧 Ego Portal 的任务上传完整回归。
  3. 再部署支持标定模式的 Ego Portal。

回滚 Ego Portal 不影响原任务上传。回滚 Keystone 前必须停止新标定上传，否则旧 Keystone 无法识别 calibration_capture。

验收清单

  • 旧客户端不发送 upload_kind 时仍能创建 Episode 并完成 Task。
  • 标定上传不携带 task、plan、workstation 也能获得受限 STS。
  • 标定上传必须携带非空 camera_serial；同一 Session 中任一 Capture 改变该值都返回 FailedPrecondition。
  • 状态查询使用持久 Device-Authorization 或临时 Device JWT 均成功；同时发送两个请求头返回 400，缺失或无效凭证返回 401，其他设备的 Session 返回 404。
  • 每条原始 MCAP 只创建一个 Orbit Job；Job 内先拆分双目并提取非空 IMU，再运行标定；结果 JSON 的 source 与冻结的原始 capture.mcap 完全一致。
  • 同一 Capture 重试 CompleteUpload 不产生重复记录。
  • 失败结果不会结束 Session，首条成功结果会原子结束 Session。
  • Session 成功后的新上传被拒绝，在途上传被安全收口。
  • protobuf 与公共上传 SDK 无变更。
Keystone 保留旧战线，新增标定分流；传输主干不重写，业务语义不混用。
