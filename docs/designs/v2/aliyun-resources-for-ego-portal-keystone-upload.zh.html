00

执行结论

使用当前阿里云 CLI default profile 创建一套专用资源，不复用 data-platform 现有资源。

Keystone 长期 AK/SK 不直接拥有 OSS 写权限；它只用于 AssumeRole。iOS 端只拿到短期、受限到 ego-portal-lite/* 的 STS。

本机已确认存在阿里云 CLI：/usr/local/bin/aliyun，版本 3.3.4。当前 default profile 凭证有效，默认 region 是 cn-shanghai。

02

权限模型

权限链路分两层，长期凭证与对象写权限隔离。

  1. Keystone 持有 keystone-dgw-poc 的 AK/SK。
  2. keystone-dgw-poc 只能调用 sts:AssumeRole 扮演 keystone-ego-upload-role。
  3. keystone-ego-upload-role 拿到的临时 STS 只能写 OSS bucket 下的 ego-portal-lite/* prefix。
  4. 第一版不授予读权限，因为 Keystone 不做 HeadObject 校验。
03

策略内容

策略文本会在执行时带入真实 AccountId 和最终 bucket 名。

Role 写 OSS 策略

{
  "Version": "1",
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "oss:PutObject",
      "oss:InitiateMultipartUpload",
      "oss:UploadPart",
      "oss:CompleteMultipartUpload",
      "oss:AbortMultipartUpload",
      "oss:ListParts"
    ],
    "Resource": [
      "acs:oss:*:*:archebase-keystone-poc/ego-portal-lite/*"
    ]
  }]
}

User AssumeRole 策略

{
  "Version": "1",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["sts:AssumeRole"],
    "Resource": [
      "acs:ram::<ACCOUNT_ID>:role/keystone-ego-upload-role"
    ]
  }]
}

Role 信任策略

{
  "Version": "1",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {
      "RAM": [
        "acs:ram::<ACCOUNT_ID>:user/keystone-dgw-poc"
      ]
    },
    "Action": "sts:AssumeRole"
  }]
}
04

CLI 执行步骤

以下是会真实创建资源的计划。执行前需要联网和云资源写权限。

获取账号 ID

aliyun sts GetCallerIdentity

创建 OSS Bucket

aliyun oss mb oss://archebase-keystone-poc --region cn-shanghai
aliyun oss set-acl oss://archebase-keystone-poc private
aliyun oss stat oss://archebase-keystone-poc

创建 RAM User

aliyun ram CreateUser \
  --UserName keystone-dgw-poc \
  --DisplayName keystone-dgw-poc

创建 RAM Role

aliyun ram CreateRole \
  --RoleName keystone-ego-upload-role \
  --Description "Keystone ego-portal-lite OSS upload POC role" \
  --MaxSessionDuration 3600 \
  --AssumeRolePolicyDocument '<TRUST_POLICY_JSON>'

创建并绑定 Role 写 OSS 权限

aliyun ram CreatePolicy \
  --PolicyName KeystoneEgoUploadRolePolicy \
  --Description "Allow Keystone POC STS credentials to upload ego-portal-lite captures" \
  --PolicyDocument '<ROLE_OSS_WRITE_POLICY_JSON>'

aliyun ram AttachPolicyToRole \
  --RoleName keystone-ego-upload-role \
  --PolicyType Custom \
  --PolicyName KeystoneEgoUploadRolePolicy

创建并绑定 User AssumeRole 权限

aliyun ram CreatePolicy \
  --PolicyName KeystoneDgwAssumeRolePolicy \
  --Description "Allow Keystone POC RAM user to assume upload role" \
  --PolicyDocument '<USER_ASSUME_ROLE_POLICY_JSON>'

aliyun ram AttachPolicyToUser \
  --UserName keystone-dgw-poc \
  --PolicyType Custom \
  --PolicyName KeystoneDgwAssumeRolePolicy

创建 Keystone 专用 AK/SK

aliyun ram CreateAccessKey --UserName keystone-dgw-poc

AccessKeySecret 只显示一次，需要立即写入部署 secret，不写入仓库。

06

验证计划

先验证云资源，再验证 Keystone 到 iOS 的端到端链路。

  • 用 Keystone RAM User AK/SK 调 AssumeRole，确认返回 AccessKeyId、AccessKeySecret、SecurityToken、Expiration。
  • 用临时 STS 写入测试对象：oss://archebase-keystone-poc/ego-portal-lite/probe.txt。
  • Keystone 启动 dgwcompat，iOS base URL 指向 Keystone POC host。
  • Keystone 日志出现 CreateLogicalUpload 和 CompleteUpload。
  • OSS 中出现 ego-portal-lite/{device_id}/{capture_id}/{upload_id}/capture.mcap。
07

回滚计划

删除资源前先解绑策略；删除 bucket 前必须清空对象。

aliyun ram DetachPolicyFromRole \
  --RoleName keystone-ego-upload-role \
  --PolicyType Custom \
  --PolicyName KeystoneEgoUploadRolePolicy

aliyun ram DetachPolicyFromUser \
  --UserName keystone-dgw-poc \
  --PolicyType Custom \
  --PolicyName KeystoneDgwAssumeRolePolicy

aliyun ram DeletePolicy --PolicyName KeystoneEgoUploadRolePolicy
aliyun ram DeletePolicy --PolicyName KeystoneDgwAssumeRolePolicy

aliyun ram ListAccessKeys --UserName keystone-dgw-poc
aliyun ram DeleteAccessKey --UserName keystone-dgw-poc --UserAccessKeyId <ACCESS_KEY_ID>

aliyun ram DeleteRole --RoleName keystone-ego-upload-role
aliyun ram DeleteUser --UserName keystone-dgw-poc

aliyun oss rm oss://archebase-keystone-poc/ego-portal-lite/ -r -f
aliyun oss rm oss://archebase-keystone-poc
执行前确认：使用当前 default profile；创建专用 RAM User、RAM Role、两条自定义策略和私有 OSS bucket；AK/SK 只输出给 Keystone 部署配置，不写入仓库。
