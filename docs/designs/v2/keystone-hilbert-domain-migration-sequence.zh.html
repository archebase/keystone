目标模型总览

Keystone Service
  ├─ Hilbert Service Identity       (PR-1)
  │   └─ workspace/list-available -> local projection
  │
  ├─ Workspace                      (business ownership / permission boundary)
  │   ├─ id=0 default workspace     (local-only, cloud sync disabled)
  │   ├─ id=<hilbert_workspace_id>  (source=hilbert)
  │   ├─ DataCollectors
  │   ├─ Robots / Devices
  │   ├─ Workstations
  │   ├─ Hilbert DCPlans             (projection foundation landed)
  │   ├─ Tasks                       (plan-driven local execution slices)
  │   └─ Episodes / RawData uploads  (schema has dc_plan id; runtime not wired yet)
  │
  └─ Local Execution Support
      └─ Recorder / transfer connection state
字段 角色 不能再表达什么
workspace_id 业务归属、权限边界、前端全局上下文；0 是本地 default。过渡期旧列名 organization_id 只作为数据库兼容承载。 不能从地点、设备或本地执行环境推导，也不能把 default 自动上传到 Hilbert；不能在新 API 中继续暴露为 organization 语义。
dc_plan_id Keystone task/episode 关联的 Hilbert 计划投影 ID；该 ID 等于 Hilbert dc_plan.id。 不能再用 order_id、batch_id、factory_id、scene_id 承担跨系统业务元信息语义。
hilbert_*_id 后续与 Hilbert 资源同步时的外部映射 Workspace 例外：workspaces.id 第一阶段直接使用 Hilbert workspace ID。

Workspace 投影与 Default 兜底

第一刀 Hilbert source of truth

建立 Workspace 来源规则：Keystone 不管理 Workspace，只缓存 Hilbert 可访问 Workspace，并保留本地 default。

  • workspaces.id 直接使用 Hilbert workspace ID。
  • workspaces.id=0 是 Keystone 保留的 default workspace。
  • 新增独立 HilbertConfig 和 Hilbert service identity provider。
  • 启动时和手动触发时调用 /workspace/list-available，只 upsert，不删除缺失 workspace。
  • Workspace API 只提供 GET /workspaces、GET /workspaces/:id、POST /workspaces/sync。
  • Synapse 删除组织管理，新增只读 Workspace 状态页，暂不做全局 selector。

Workspace 运营资源最小投影

PR-2.5 PR-3 prerequisite

PR-3 不在拉取数采计划时创建设备、机器人或采集员主数据，所以必须先有最小资源投影，让 dc_plan.operator 和 dc_plan.dc_device_id 能匹配 Keystone 本地执行资源。

  • 已完成 资源同步固定挂在 Workspace 同步上：启动同步和 POST /workspaces/sync 都先 upsert Workspace，再按 Workspace 独立事务同步资源。
  • 采集员来源是 Hilbert workspace.admins + workspace.members，逐个查 /v1/console/account/query；只要账号可查询，就投影为 Keystone data_collectors，不再按 role、externalUserType 或 status 做额外过滤。
  • 采集员写入 data_collectors.operator_id = account.code，data_collectors.organization_id 暂时承载 Hilbert workspace ID。
  • 数采设备来自 /v1/data-collection/dc-device/query?workspaceId=...，写入 robots.device_id = dc_device.id 的十进制字符串，并把 dc_device.name 保存到 metadata.hilbert_dc_device_name；robots API 顶层返回 device_name，Synapse 设备列表优先显示名称、兜底 ID。
  • 同步 Hilbert dc_device_type 到 Keystone robot_types，并为每个 Hilbert Workspace 创建 / 复用一个 workspace compat factory 以满足 robots.factory_id；factory slug = hilbert_workspace_<workspace_id>，名称带 workspace ID 以避免同名 Workspace 冲突。
  • 旧列 data_collectors.organization_id、workstations.organization_id 在清理前承载 workspace ID；对外和新代码语义称 workspace_id。
  • 新建采集员和机器人默认 active；已存在记录只覆盖 Hilbert 权威投影字段和 metadata，不覆盖本地 status、asset_id、password_hash 等运营字段。
  • Hilbert 消失资源不自动软删；非 Hilbert robot / collector / robot type 冲突资源跳过并写入 resource_sync summary。
  • POST /workspaces/sync response 已返回 resource_sync summary；启动同步没有 HTTP response，必须输出同一套聚合日志，便于排查资源投影失败。
  • 本阶段只提供 PR-3 所需的资源可解析性，不生成 task，不做 scoped admin shell，不清理旧设备管理页面。
  • 实施细节见 PR-2.5 Workspace 运营资源最小投影。

计划驱动 Task 拆分

PR-3 替代 order/batch

这是 PR-2.5 资源投影之后的主干工作。Keystone 已能缓存 Hilbert 数采计划，并已在同步计划后按计划目标数量自动补齐本地 task。task 是执行切片；PR-3 先用兼容 order / batch 壳稳住旧 runtime，但新语义事实来源必须是 dc_plan_id。

  • 已完成 POST /workspaces/:workspace_id/dc-plans/sync 成功 upsert 本次计划后，自动逐计划补齐 task。
  • 已完成 按 target_count 补齐缺口；重复同步不超额，target 变大只新增，target 变小不删除旧 task。
  • PR-3 不在拉取数采计划时创建设备、机器人或采集员；这些应来自 Workspace 级同步。
  • 已完成 按 operator + dc_device_id 查找 robot / collector；同一 robot 或 collector 已有 current binding 时，自动创建 plan-specific 非 current workstation，避免多计划共享设备时被当前绑定唯一性阻塞。
  • 已完成 每个计划创建 / 复用一个 compat order 和稳定 batch，batch_id = dcplan_<dc_plan_id>。
  • 已完成 按 dc_factory_id 创建 / 复用 plan compat factory，满足 task / order / batch / scene runtime 兼容。
  • PR-2.5 的 workspace compat factory 只用于 robots.factory_id；PR-3 自动创建工位和 task 使用 plan compat factory。
  • 已完成 按 dc_type 创建 compat SOP / scene / subscene；旧字段只作为 runtime 兼容层。
  • task list/detail/config 增加 dc_plan_id、workspace_id、dc_type 等计划字段。
  • 已完成 单计划缺资源时 blocked，不拖垮整批计划同步；响应返回 per-plan generation summary。
  • 已验收 workspace B 四个计划目标数 1、100、10、1，同步后 task 总数为 112，且不再出现同设备多计划的 binding_conflict。
  • 实施细节见 PR-3 Hilbert 数采计划驱动 Task 生成。

上传只携带数采计划 ID

PR-4 raw data metadata

Keystone 上传采集数据时不再向 Hilbert 重建 order/batch 元信息。只要通过 dc_plan_id 找到 Hilbert 计划投影，并把该投影的 id 作为 Hilbert dcPlanId，Hilbert 就能根据计划找到对应的数据元信息。

  • episodes 创建时从 task 复制 dc_plan_id；workspace_id 先通过 dc_plan.workspace_id 派生。
  • Episode 创建路径必须实际写入或可稳定派生 dc_plan_id，不能只停留在 schema 预留。
  • 云同步 payload 携带 workspace_id、Hilbert dcPlanId、本地 task_id 和文件制品信息。
  • 不上传 order_id、batch_id 或本地 order/batch 元信息。
  • 不上传本地 scene_id / subscene_id；Hilbert 根据计划 ID 解析数据元信息。
  • Hilbert raw data / dataset 创建路径必须拒绝 workspace_id=0、空 dc_plan_id 或找不到 dc_plan 投影。
  • 保留 Keystone 本地 episode、MCAP、sidecar、QA 状态，作为边缘执行和排障记录。

删除 Order / Batch 主路径

PR-7 破坏式清理

当计划驱动 task、上传链路、scoped admin 和 Axon task runtime 都不再依赖 compat orders / batches 后，删除本地主业务路径，避免两套生产组织概念并存。本阶段只处理 order/batch，不抢先删除 factory、robot type、SOP、scene/subscene runtime。

  • 删除或停用 /orders、/batches 写路径和 Synapse 管理入口。
  • 任务列表、统计、dashboard 改以 workspace_id、dc_plan_id 和 task 状态为主筛选。
  • V2 baseline schema 可直接移除 orders / batches，或仅保留临时只读迁移观察表。
  • 删除 tasks.order_id、tasks.batch_id 的 runtime 依赖；scene_id / subscene_id runtime 停用留给 PR-8A。
  • 删除 episodes.order_id、episodes.batch_id 的 runtime 依赖；episode.scene_id runtime 停用留给 PR-8A。
  • Swagger 与 Synapse API wrapper 删除 order/batch 作为业务入口的字段和路由。
8A

旧生产元信息 Runtime 停用

PR-8A stop using old concepts

先从 runtime 路径停用 factory、robot type、SOP、scene/subscene，避免一次性删表导致任务配置、统计或设备注册断裂。

  • 设备注册、设备列表、统计、大屏和任务查询不再接受 factory、scene、SOP、robot type 筛选。
  • 删除 sops、scenes、subscenes 作为生产元信息来源的 runtime 依赖。
  • 删除 robot_types / device_types 本地字典在 runtime 中的校验、筛选和设备编号序列依赖。

PR-5 Workspace 运营实体管理与归属清理 在 PR-2.5 最小资源投影基础上，完善 data_collectors、设备投影和 workstations 的管理 API、筛选和页面； 删除这些接口中的 factory、scene、SOP、robot type 创建和筛选依赖。 不引入登录后的 Workspace shell；不删除 order/batch；不删除旧表。 未完成： 数据采集员、设备和工位仍有旧归属 / 旧筛选依赖，尚不能稳定支撑 scoped admin。
PR-6 Workspace Scoped Admin Shell 管理员登录后进入 Workspace 选择目录；选择后进入 scoped admin shell； 设备、数据采集员、工位、数采计划、数据明细、数据统计均在当前 workspace_id 下展示。 不使用 localStorage 作为 Workspace 事实来源；不开放 Workspace 创建、编辑、删除。 未完成： 当前 Synapse 只有只读 Workspace 状态页，尚未提供登录后的 Workspace 选择目录和 scoped admin 路由。
PR-7 删除 Order / Batch 主路径 在 task runtime、Axon config、上传链路和统计不再依赖 compat order/batch 后， 删除或停用 /orders、/batches 写路径和 Synapse 管理入口； 统计、dashboard、任务查询改以 workspace_id、dc_plan_id 和 task 状态为主。 不处理旧表最终删除；不停用 factory、robot type、SOP、scene/subscene runtime。 未完成： 当前 order/batch 仍是本地生产组织入口。
PR-8A 旧生产元信息 Runtime 停用 runtime 路径停止依赖 factory、robot type、SOP、scene/subscene； Axon 任务配置从数采计划配置快照读取。 不删除旧表和旧 API 文件；只隐藏或停用 runtime 使用。 未完成： factory、robot type、SOP、scene/subscene 仍散落在任务配置、统计、设备注册和 UI 中。
PR-8B 旧表 / Swagger / Synapse 清理 删除旧表、旧路由、Swagger、Synapse API wrapper、旧页面、option adapter、旧字段和旧测试夹具。 不改变 dc_plan -> task -> episode 主链路语义。 未完成： 依赖 PR-8A 完成 runtime 停用后再执行。
结合当前代码，PR-1A / PR-1B / PR-1C 已完成，PR-2 后端基础、PR-2.5 Workspace 资源投影和 PR-3 计划驱动 task 拆分也已完成。 下一阶段不应继续停留在计划投影、资源投影或 task 拆分层； 现在应进入 PR-4：让 episode 创建和上传链路以 Hilbert 数采计划 ID 作为元信息入口。 order/batch 仍是现有 runtime，但不能再作为长期目标模型；Hilbert 数采计划是生产主对象， Keystone task 是计划拆分后的本地执行切片。
04

已落地能力锁定

PR-1 的目标是建立 Workspace 来源规则，而不是提供 Keystone 本地 Workspace 管理。 详细决策已拆分到独立文档： PR-1 Workspace 来源规则决策锁定。

当前实现进度：PR-1A / PR-1B / PR-1C 已完成。Keystone 后端已具备 id=0 default workspace、 只读 GET /workspaces / GET /workspaces/:id、V2 baseline schema、 POST /workspaces/sync、Hilbert service identity bootstrap 和事务 upsert 支撑。 PR-1C 也已接入 Synapse 只读 Workspace 状态页和手动同步入口，但仍不引入全局 selector 或当前 workspace。 PR-2 已接入 Hilbert dc_plan 查询、Keystone dc_plan 投影表、只读列表和单 Workspace 手动同步； PR-2.5 已在 Workspace 同步中固定投影采集员、数采设备、设备类型和 workspace compat factory； PR-3 已把 task 生成改为计划驱动；episode 写入和上传 payload 尚未改为只依赖计划 ID。

核心不变量

  • Hilbert 是 Workspace source of truth；Keystone 只保存可访问 Workspace 的本地投影。
  • workspaces.id=0 是 Keystone 保留 default workspace，不对应 Hilbert Workspace。
  • 过渡期旧数据库列 organization_id 只承载 Workspace ID；新 API、文档和业务语义都称 workspace_id。
  • default workspace 允许本地采集和 Keystone MinIO 本地制品上传，但禁止进入 Hilbert / 云同步。
  • Keystone 不维护 Workspace 级上传资格开关；source='hilbert' 的 Workspace 可作为 Hilbert 归属，最终权限由 Hilbert API 判定。
  • PR-1 阶段 Hilbert admins/members 只展示，不驱动 Keystone 本地权限。
  • PR-2.5 开始，Hilbert admins/members 作为 Keystone 数采员投影来源；登录侧不再额外校验 Hilbert externalUserType，而以本地 active data_collectors 记录作为数采员准入。
05

验收标准

每个阶段必须满足

  • OpenAPI / Swagger 与 handler 字段一致。
  • Synapse API wrapper、表单、筛选、详情字段一致。
  • Keystone 单元测试和构建通过。
  • 新增字段没有旧名残留在 runtime path。
  • default workspace 的本地可用性和云同步禁止规则有测试覆盖。

最终必须满足

  • 业务数据均可按 workspace_id 查询。
  • 数采计划成为生产主对象，task 均可追溯到 dc_plan_id 或未来 local_dc_plan_id。
  • Keystone runtime 不再依赖 factory、scene、subscene 推导业务元信息。
  • 设备投影不能跨 workspace 绑定数采员。
  • Keystone runtime 不再依赖 robot type / device type 本地字典。
  • 一个 Keystone 可消费多个 Hilbert workspace。
  • workspace_id=0 的数据不会自动进入 Hilbert / 云同步。

PR-1 必须满足

  • 未配置 Hilbert 时，GET /workspaces 返回 id=0 的 default workspace，且不暴露 upload_enabled 字段。
  • Hilbert 同步成功后，GET /workspaces 返回 default 加本地缓存的 Hilbert workspaces。
  • Hilbert 后续失败时，GET /workspaces 仍返回上次缓存加 default；手动 sync 返回失败。
  • Swagger 不暴露 workspace 创建、更新、删除接口。
  • Synapse 只读状态页展示 default，并明确标记本地和不可云同步。

本地上传与云同步验收

  • default workspace 下允许本地采集、Axon transfer 上传 MCAP 到 Keystone MinIO、生成本地 Episode。
  • cloud sync worker 和任何 Hilbert raw data / dataset 创建路径必须拒绝 workspace_id=0。
  • Hilbert 上传路径必须拒绝缺失 dc_plan_id 或找不到 Hilbert dc_plan 投影，不能用 order/batch/scene/subscene 元信息替代计划 ID。
  • Workspace 级别不设置本地上传资格开关；default workspace 仍必须被 Hilbert raw data / dataset 创建路径拒绝。

PR-2 / PR-3 / PR-4 必须满足

  • PR-2：dc_plan 严格镜像 Hilbert 计划，id 等于 Hilbert dc_plan.id，支持按 workspace_id 只读查询和手动同步。当前后端已满足。
  • PR-2：tasks / episodes 已具备保存 dc_plan_id 与 local_dc_plan_id 的 schema 基础。PR-3 已让 task 写入 dc_plan_id；episode runtime wiring 留给 PR-4。
  • PR-2.5：Workspace sync 固定同步资源，不加开关；Workspace upsert 成功后，逐 Hilbert Workspace 独立事务同步采集员、数采设备、设备类型和 workspace compat factory。
  • PR-2.5：Workspace 资源同步后，dc_plan.operator 能匹配 data_collectors.operator_id，dc_plan.dc_device_id 能匹配 robots.device_id。
  • PR-2.5：Hilbert workspace 的 admins + members 都可以成为数采员投影，不再加 enabled + external_user + data_supplier 过滤；新建资源默认 active；Hilbert 消失资源不自动软删；冲突资源跳过并进入 response summary。
  • PR-3：同步计划后自动补齐 task；同一 Hilbert 数采计划重复同步或重复触发时不会生成超额 task。
  • PR-3：robot / collector 主数据缺失时不自动创建，单计划 blocked；工位缺失但资源有效且 workspace 一致时可自动创建。
  • PR-3：同一设备被多个计划复用时，后续计划创建 plan-specific 非 current workstation，不应因为 current binding 唯一性产生 binding_conflict。
  • PR-3：自动创建工位和 task 使用 dc_plan.dc_factory_id 对应的 plan compat factory，不使用 PR-2.5 的 workspace compat factory。
  • PR-3：workspace B 验收样例中，四个计划 target_count 1、100、10、1 应生成共 112 条 task。
  • PR-3：Axon 取配置、任务开始/完成回调仍能基于 Keystone task 正常工作，并在 config 中追加计划字段。
  • PR-4：episode 创建路径必须从 task 写入或稳定派生 dc_plan_id，不能只依赖 schema 预留。
  • PR-4：上传到 Hilbert 的 raw data / dataset 请求通过 dc_plan_id 找到 Hilbert 投影，再使用该投影的 id 作为 Hilbert dcPlanId，并由 dc_plan.workspace_id 派生 Workspace。

PR-5 运营实体归属必须满足

  • 数据采集员、设备投影、工位 / 当前绑定视图均可按 workspace_id 查询。
  • 跨 workspace 的设备与采集员绑定被后端拒绝。
  • 设备、采集员、工位接口不再接受 factory、scene、SOP、robot type 作为创建必填项。
  • Synapse 对应 API wrapper 已具备 workspace_id 入参，但尚不要求登录后 scoped shell。

Workspace Scoped Admin 必须满足

  • 管理员登录成功后默认进入 Workspace 选择目录，而不是直接进入某个业务页。
  • 选择 Workspace 后，设备、数据采集员、工位、数采计划、数据明细、数据统计都在路由中的 workspace_id 下查询。
  • 刷新页面后 Workspace 上下文由 URL 恢复，不依赖 localStorage。
  • 切换 Workspace 必须回到选择目录或显式切换入口，不能隐式改变业务查询范围。
  • default workspace 可查看本地数据，但 Hilbert 上传和云同步动作必须禁用或拒绝。

PR-8A / PR-8B 必须满足

  • PR-8A：runtime 路径不再读取 factory、robot type、SOP、scene/subscene 来生成 task config、统计或筛选；PR-7 只负责 order/batch 主路径删除。
  • PR-8A：旧 UI 如果暂时保留，必须隐藏写入口或标记只读，不能继续创建旧概念数据。
  • PR-8B：旧表、旧 API、Swagger、Synapse API wrapper、页面和 option adapter 被删除。
  • PR-8B：测试夹具和 OpenAPI 中不再出现旧生产元信息字段。
06

明确后置的问题

  • Hilbert 数采计划除现有单 Workspace 手动同步外，是否还需要启动同步、主动轮询、webhook，或三者并存。
  • Keystone 旧 sops 数据和 UI 是直接删除，还是短期隐藏为只读历史配置。
  • Keystone 旧 scenes / subscenes 数据和 UI 是直接删除，还是短期隐藏为只读历史配置。
  • Keystone 旧 robot_types / device_types 数据和 UI 是直接删除，还是短期隐藏为只读历史配置。
  • 计划撤销或关闭后，未执行 task 是否取消，已完成 episode 是否仍允许上传。
  • episode 与 Hilbert raw_data / dataset 的同步边界。
  • default workspace 数据如何显式补绑到 Hilbert workspace，以及需要记录哪些审计字段。
  • Hilbert 不再返回某个 workspace 时，是否新增 access_status 和历史数据可见策略。
  • Workspace 撤权后，未同步数据是否继续允许云同步，还是必须暂停等待人工处理。
这些问题不是不重要，而是不应该挡住数采计划成为生产主对象。 PR-2 已建立计划投影和字段基础，PR-2.5 已补齐 Workspace 资源投影，PR-3 已完成计划驱动 task 拆分； 现在应推进 PR-4 切 episode 和上传协议。
