不迁历史数据

直接修改 V2 baseline schema，不写历史 ALTER TABLE 回填脚本。

不保留兼容 API

冻结领域映射和非目标

文档先行 不改代码

把 Keystone 与 Hilbert 的实体对应关系写清楚，特别是哪些只是归属迁移，哪些是真正语义替换。

  • 确认 organization -> Hilbert workspace projection。
  • 确认 workspace_id=0 -> default local-only workspace。
  • 确认 Keystone 删除 factory / dc_factory 本地概念。
  • 确认 Hilbert 通过 dc_plan_id 对应的 Hilbert dc_plan.id 解析 factory、scene 等数据元信息。
  • 确认 Keystone 不保留机器人类型 / 设备类型本地字典。
  • 确认 robot -> Hilbert dc_device execution projection，只保留本地连接和执行所需字段。
  • 确认 Hilbert dc_plan -> Keystone task generation source。
  • 确认 task/episode -> Keystone local execution and artifact records。
  • 标记 order/batch 为待删除的旧生产组织概念。
1

Workspace 投影与 Default 兜底

第一刀 Hilbert source of truth

建立 Workspace 来源规则：Keystone 不管理 Workspace，只缓存 Hilbert 可访问 Workspace，并保留本地 default。

  • workspaces.id 直接使用 Hilbert workspace ID。
  • workspaces.id=0 是 Keystone 保留的 default workspace。
  • 新增独立 HilbertConfig 和 Hilbert service identity provider。
  • 启动时和手动触发时调用 /workspace/list-available，只 upsert，不删除缺失 workspace。
  • Workspace API 只提供 GET /workspaces、GET /workspaces/:id、POST /workspaces/sync。
  • Synapse 删除组织管理，新增只读 Workspace 状态页，暂不做全局 selector。
2

Hilbert 数采计划投影基础

PR-2 主链路入口

先把 Hilbert 下发的数采计划作为生产主对象投影到 Keystone。本阶段不围绕 order / batch 改名，不生成 task，不切上传协议，只建立 Hilbert dc_plan 镜像、只读查询、手动同步和后续计划字段基础。

  • 新增 dc_plan 表，严格作为 Hilbert dc_plan 投影，dc_plan.id 等于 Hilbert 计划 ID。
  • dc_plan 字段保持 Hilbert 当前必填约束，追加 raw_payload、last_synced_at、sync_error 和本地行时间。
  • 本地计划不进入 dc_plan；后续单独设计 local_dc_plan。
  • tasks 和 episodes 预留 dc_plan_id 与 local_dc_plan_id，但本 PR 不写入。
  • 新增 GET /dc-plans 只读列表和 POST /workspaces/:workspace_id/dc-plans/sync 单 Workspace 手动同步。
  • 保留现有 order / batch runtime，不在本 PR 一次性切换派发流程。
  • 删除 workspaces.upload_enabled；Keystone 不控制 Workspace 级上传资格，最终权限由 Hilbert API 判定。
  • 实施细节见 PR-2 Hilbert 数采计划投影实施细节。
3

计划驱动 Task 拆分

PR-3 替代 order/batch

Keystone 接收或同步 Hilbert 数采计划后，按计划目标数量自动生成本地 task。task 是执行切片，不再从本地 order / batch 派生业务语义。

  • 新增计划同步或计划接收入口，确保 Keystone 能拿到 Hilbert 下发的计划。
  • 按计划目标数量生成 tasks，每个 task 持有 dc_plan_id、workspace_id 和本地执行状态。
  • 计划元信息不再拆成 Keystone scene / subscene，本地 task 只保存执行所需的计划配置快照。
  • 任务状态、录制回调、Axon 取配置继续走 Keystone 本地链路。
  • 新增重复拆分保护，避免同一计划被多次生成超额 task。
  • Synapse 生产入口从 order/batch 管理切到数采计划状态和计划下 task 列表。
4

上传只携带数采计划 ID

PR-4 raw data metadata

Keystone 上传采集数据时不再向 Hilbert 重建 order/batch 元信息。只要通过 dc_plan_id 找到 Hilbert 计划投影，并把该投影的 id 作为 Hilbert dcPlanId，Hilbert 就能根据计划找到对应的数据元信息。

  • episodes 创建时从 task 复制 workspace_id 和 dc_plan_id。
  • 云同步 payload 携带 workspace_id、Hilbert dcPlanId、本地 task_id 和文件制品信息。
  • 不上传 order_id、batch_id 或本地 order/batch 元信息。
  • 不上传本地 scene_id / subscene_id；Hilbert 根据计划 ID 解析数据元信息。
  • Hilbert raw data / dataset 创建路径必须拒绝 workspace_id=0、空 dc_plan_id 或找不到 dc_plan 投影。
  • 保留 Keystone 本地 episode、MCAP、sidecar、QA 状态，作为边缘执行和排障记录。
5

Workspace 运营实体归属

PR-5 operational scope

在 Synapse scoped admin 之前，先让设备投影、数据采集员和工位具备可靠的 workspace_id 归属与筛选能力。

  • data_collectors 使用 workspace_id 归属，列表、详情、创建和筛选统一改参。
  • robots 改造为 Hilbert dc_device 的本地执行投影，或重命名为 devices。
  • 设备投影保存 workspace_id、Hilbert device ID、本地连接状态、最后心跳和执行能力快照。
  • workstations 如保留，只作为当前绑定 / 执行会话视图，并持有 workspace_id。
  • 删除设备、采集员、工位接口中的 factory、scene、SOP、robot type 筛选和创建依赖。
  • Synapse 暂时只改 API wrapper 和页面入参，不在本 PR 引入登录后的 Workspace shell。
6

Workspace 选择目录与 Scoped Admin

PR-6 Synapse shell

管理员登录后先进入 Workspace 选择目录；选择一个 Workspace 后进入该 Workspace 的管理后台，所有业务页面都带当前 workspace_id 查询。

  • 登录成功默认进入 /admin/workspaces/select 或等价选择目录。
  • 选择后进入 scoped admin shell，例如 /admin/workspaces/:workspaceId/devices。
  • 侧边栏包含设备、数据采集员、工位、数采计划、数据明细、数据统计。
  • 当前 Workspace 上下文由路由参数表达，不写 localStorage 作为事实来源。
  • 设备、数据采集员、工位、数采计划、数据明细、数据统计页面统一从路由 workspace_id 取 scope。
  • default workspace 可进入本地管理后台，但所有 Hilbert 上传入口保持禁用。
7

删除 Order / Batch 主路径

PR-7 破坏式清理

当计划驱动 task、上传链路和 scoped admin 都稳定后，删除本地 orders / batches 的主业务路径，避免两套生产组织概念并存。

  • 删除或停用 /orders、/batches 写路径和 Synapse 管理入口。
  • 任务列表、统计、dashboard 改以 workspace_id、dc_plan_id 和 task 状态为主筛选。
  • V2 baseline schema 可直接移除 orders / batches，或仅保留临时只读迁移观察表。
  • 删除 tasks.order_id、tasks.batch_id、tasks.scene_id、tasks.subscene_id 的 runtime 依赖。
  • 删除 episodes.order_id、episodes.batch_id、episodes.scene_id 的 runtime 依赖。
  • Swagger 与 Synapse API wrapper 删除 order/batch 作为业务入口的字段和路由。
8A

旧生产元信息 Runtime 停用

PR-8A stop using old concepts

先从 runtime 路径停用 factory、robot type、SOP、scene/subscene，避免一次性删表导致任务配置、统计或设备注册断裂。

  • Axon 任务配置需要的执行参数从数采计划配置快照读取，不再从 SOP 或 scene/subscene 表拼装。
  • 设备注册、设备列表、统计、大屏和任务查询不再接受 factory、scene、SOP、robot type 筛选。
  • 删除 sops、scenes、subscenes 作为生产元信息来源的 runtime 依赖。
  • 删除 robot_types / device_types 本地字典在 runtime 中的校验、筛选和设备编号序列依赖。
  • 保留旧表和旧 UI 的短期隐藏或只读策略，给 PR-8B 做最终清理。
8B

旧表 / Swagger / Synapse 清理

PR-8B schema cleanup

runtime 已停用后，再删除旧表、路由、Swagger、Synapse API wrapper、旧页面和 option adapter。

  • 删除 factories、robot_types、sops、scenes、subscenes 的旧管理入口和 API。
  • 删除相关 Swagger 路由、Synapse 页面、API wrapper、option adapter 和菜单项。
  • 删除旧字段、旧索引和旧测试夹具中的 factory、robot type、SOP、scene/subscene 依赖。
  • 设计 Workspace 撤权 / 下线后的 access_status 和历史数据可见性策略。

05

验收标准

每个阶段必须满足

  • OpenAPI / Swagger 与 handler 字段一致。
  • Synapse API wrapper、表单、筛选、详情字段一致。
  • Keystone 单元测试和构建通过。
  • 新增字段没有旧名残留在 runtime path。
  • default workspace 的本地可用性和云同步禁止规则有测试覆盖。

最终必须满足

  • 业务数据均可按 workspace_id 查询。
  • 数采计划成为生产主对象，task 均可追溯到 dc_plan_id 或未来 local_dc_plan_id。
  • Keystone runtime 不再依赖 factory、scene、subscene 推导业务元信息。
  • 设备投影不能跨 workspace 绑定数采员。
  • Keystone runtime 不再依赖 robot type / device type 本地字典。
  • 一个 Keystone 可消费多个 Hilbert workspace。
  • workspace_id=0 的数据不会自动进入 Hilbert / 云同步。

PR-1 必须满足

  • 未配置 Hilbert 时，GET /workspaces 返回 id=0 的 default workspace，且不暴露 upload_enabled 字段。
  • Hilbert 同步成功后，GET /workspaces 返回 default 加本地缓存的 Hilbert workspaces。
  • Hilbert 后续失败时，GET /workspaces 仍返回上次缓存加 default；手动 sync 返回失败。
  • Swagger 不暴露 workspace 创建、更新、删除接口。
  • Synapse 只读状态页展示 default，并明确标记本地和不可云同步。

本地上传与云同步验收

  • default workspace 下允许本地采集、Axon transfer 上传 MCAP 到 Keystone MinIO、生成本地 Episode。
  • cloud sync worker 和任何 Hilbert raw data / dataset 创建路径必须拒绝 workspace_id=0。
  • Hilbert 上传路径必须拒绝缺失 dc_plan_id 或找不到 Hilbert dc_plan 投影，不能用 order/batch/scene/subscene 元信息替代计划 ID。
  • Workspace 级别不设置本地上传资格开关；default workspace 仍必须被 Hilbert raw data / dataset 创建路径拒绝。

PR-2 / PR-3 / PR-4 必须满足

  • PR-2：dc_plan 严格镜像 Hilbert 计划，id 等于 Hilbert dc_plan.id，支持按 workspace_id 只读查询和手动同步。
  • PR-2：tasks / episodes 已具备保存 dc_plan_id 与 local_dc_plan_id 的 schema 基础，但现有 runtime 不写入。
  • PR-3：同一 Hilbert 数采计划重复同步或重复触发时不会生成超额 task。
  • PR-3：Axon 取配置、任务开始/完成回调仍能基于 Keystone task 正常工作。
  • PR-4：上传到 Hilbert 的 raw data / dataset 请求通过 dc_plan_id 找到 Hilbert 投影，再使用该投影的 id 作为 Hilbert dcPlanId。

PR-5 运营实体归属必须满足

  • 数据采集员、设备投影、工位 / 当前绑定视图均可按 workspace_id 查询。
  • 跨 workspace 的设备与采集员绑定被后端拒绝。
  • 设备、采集员、工位接口不再接受 factory、scene、SOP、robot type 作为创建必填项。
  • Synapse 对应 API wrapper 已具备 workspace_id 入参，但尚不要求登录后 scoped shell。

Workspace Scoped Admin 必须满足

  • 管理员登录成功后默认进入 Workspace 选择目录，而不是直接进入某个业务页。
  • 选择 Workspace 后，设备、数据采集员、工位、数采计划、数据明细、数据统计都在路由中的 workspace_id 下查询。
  • 刷新页面后 Workspace 上下文由 URL 恢复，不依赖 localStorage。
  • 切换 Workspace 必须回到选择目录或显式切换入口，不能隐式改变业务查询范围。
  • default workspace 可查看本地数据，但 Hilbert 上传和云同步动作必须禁用或拒绝。

PR-8A / PR-8B 必须满足

  • PR-8A：runtime 路径不再读取 factory、robot type、SOP、scene/subscene 来生成 task config、统计或筛选。
  • PR-8A：旧 UI 如果暂时保留，必须隐藏写入口或标记只读，不能继续创建旧概念数据。
  • PR-8B：旧表、旧 API、Swagger、Synapse API wrapper、页面和 option adapter 被删除。
  • PR-8B：测试夹具和 OpenAPI 中不再出现旧生产元信息字段。
06

明确后置的问题

  • Hilbert 数采计划下发给 Keystone 的接口形态：主动轮询、手动同步、webhook，还是三者并存。
  • Keystone 旧 sops 数据和 UI 是直接删除，还是短期隐藏为只读历史配置。
  • Keystone 旧 scenes / subscenes 数据和 UI 是直接删除，还是短期隐藏为只读历史配置。
  • Keystone 旧 robot_types / device_types 数据和 UI 是直接删除，还是短期隐藏为只读历史配置。
  • 计划目标数量改变时，已生成 task 的补齐、冻结、取消策略。
  • 计划撤销或关闭后，未执行 task 是否取消，已完成 episode 是否仍允许上传。
  • episode 与 Hilbert raw_data / dataset 的同步边界。
  • Hilbert admins/members 是否第一时间进入 Keystone 本地权限模型。
  • default workspace 数据如何显式补绑到 Hilbert workspace，以及需要记录哪些审计字段。
  • Hilbert 不再返回某个 workspace 时，是否新增 access_status 和历史数据可见策略。
  • Workspace 撤权后，未同步数据是否继续允许云同步，还是必须暂停等待人工处理。
这些问题不是不重要，而是不应该挡住数采计划成为生产主对象。 PR-2 先建立计划投影和字段基础，PR-3 再切任务生成，PR-4 再切上传协议。
