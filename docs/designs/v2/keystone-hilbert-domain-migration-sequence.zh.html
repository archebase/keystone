本计划以新环境为前提，不考虑历史数据、不保留旧 API、不做旧字段兼容。 目标是先让 Keystone 消费 Hilbert Workspace，并用不可云同步的 default workspace 支撑本地离线采集； 再逐步替换设备、工厂和生产主链路。

00

固定前提

不迁历史数据

直接修改 V2 baseline schema，不写历史 ALTER TABLE 回填脚本。

不保留兼容 API

删除 /organizations 和 organization_id 字段，不做别名。

本地兜底不可云同步

workspace_id=0 是 default workspace，只能承载本地采集和本地制品。

实施节奏的核心约束：先锁定 Workspace 来源规则。Hilbert 是 source of truth； Keystone 只保存本地投影，并始终保留 id=0 的 default workspace。 之后再让业务数据统一站到 workspace_id 这个边界上。
01

目标模型总览

Keystone Service
  ├─ Hilbert Service Identity       (PR-1)
  │   └─ workspace/list-available -> local projection
  │
  ├─ Workspace                      (business ownership / permission boundary)
  │   ├─ id=0 default workspace     (local-only, cloud sync disabled)
  │   ├─ id=<hilbert_workspace_id>  (source=hilbert)
  │   ├─ DataCollectors
  │   ├─ Robots / Devices
  │   ├─ Workstations
  │   ├─ Orders
  │   ├─ Batches
  │   ├─ Tasks
  │   └─ Episodes
  │
  └─ Physical Dictionaries
      ├─ Factories / DCFactories    (physical collection sites)
      ├─ RobotTypes / DeviceTypes
      └─ Scenes / Subscenes         (first version: factory-scoped)
字段 角色 不能再表达什么
workspace_id 业务归属、权限边界、前端全局上下文；0 是本地 default。 不能从 factory_id 推导，也不能把 default 自动上传到 Hilbert。
factory_id 物理采集地点、现场筛选维度、设备编号分组 不能再代表租户、组织、workspace 或数据可见性。
hilbert_*_id 后续与 Hilbert 资源同步时的外部映射 Workspace 例外：workspaces.id 第一阶段直接使用 Hilbert workspace ID。
02

实施顺序

0

冻结领域映射和非目标

文档先行 不改代码

把 Keystone 与 Hilbert 的实体对应关系写清楚，特别是哪些只是归属迁移，哪些是真正语义替换。

  • 确认 organization -> Hilbert workspace projection。
  • 确认 workspace_id=0 -> default local-only workspace。
  • 确认 factory -> dc_factory / physical site。
  • 确认 robot -> workspace-scoped device + factory dimension。
  • 标记 scene/subscene、SOP、order/batch/task/episode 为后续高风险域。
1

Workspace 投影与 Default 兜底

第一刀 Hilbert source of truth

建立 Workspace 来源规则：Keystone 不管理 Workspace，只缓存 Hilbert 可访问 Workspace，并保留本地 default。

  • workspaces.id 直接使用 Hilbert workspace ID。
  • workspaces.id=0 是 Keystone 保留的 default workspace。
  • 新增独立 HilbertConfig 和 Hilbert service identity provider。
  • 启动时和手动触发时调用 /workspace/list-available，只 upsert，不删除缺失 workspace。
  • Workspace API 只提供 GET /workspaces、GET /workspaces/:id、POST /workspaces/sync。
  • Synapse 删除组织管理，新增全局 workspace selector 和只读状态页。
2

业务表统一 organization_id -> workspace_id

归属铺底 统计接口同步修改

所有业务数据统一使用非空 workspace_id；本地 API 接受 0，云同步路径拒绝 0。

  • data_collectors.workspace_id NOT NULL DEFAULT 0
  • robots.workspace_id NOT NULL DEFAULT 0
  • orders.workspace_id NOT NULL DEFAULT 0
  • batches.workspace_id NOT NULL DEFAULT 0
  • workstations.workspace_id NOT NULL DEFAULT 0
  • tasks.workspace_id NOT NULL DEFAULT 0
  • episodes.workspace_id NOT NULL DEFAULT 0
  • 所有列表、详情、统计、dashboard 删除 organization_id 参数和响应。
  • 云同步资格统一校验 workspace_id != 0、source='hilbert'、upload_enabled=true。
3

Factory 降级为物理维度

保留表 删除层级含义

factories 不再拥有 workspace，只表达采集地点、物理现场或设备编号分组。

  • 删除 FactoryResponse.orgCount。
  • 删除所有 factory -> workspace 的查询、计数和 UI 展示。
  • 保留 robots.factory_id、scenes.factory_id、device_id_sequences.factory_id。
  • 文案逐步改为“采集地点”或“数采工厂”。
4

Robot 对齐 Hilbert DCDevice

设备边界 workspace + factory

Hilbert 的 dc_device 属于 workspace，因此 Keystone 的 robot 也要成为 workspace-scoped 设备。

  • robots 新增 workspace_id。
  • 创建 robot 必填 workspace_id 和 factory_id。
  • robot 列表和详情支持 workspace_id 过滤。
  • workstation 创建时校验 robot.workspace_id == data_collector.workspace_id。
  • workstations.workspace_id 从 data collector 派生，factory_id 从 robot 派生。
5

Scene / Subscene 保守处理

待决策域 暂不硬套 Hilbert

Hilbert 当前没有 scene/subscene 的直接等价实体，第一版先保留 Keystone 现有物理环境模板语义。

  • scenes.factory_id 保留。
  • subscenes.scene_id 保留。
  • 不新增 scenes.workspace_id。
  • 记录后续决策：场景是工厂级模板、workspace 私有模板，还是二者同时存在。
6

SOP / Order / Batch / Task / Episode 主链路重建

高风险 后置

这一阶段不是字段改名，而是重新确认 Keystone 本地执行链路和 Hilbert 计划/产物链路的关系。

  • 先不要把 order 直接等同 dc_plan。
  • 先不要把 SOP 直接等同 dc_task。
  • 先确认 batch/task/episode 是否仍是 Keystone 本地执行概念。
  • 可先增加 nullable 外部映射字段：hilbert_plan_id、hilbert_raw_data_id、hilbert_dataset_id。
7

Hilbert 资源同步扩展

服务身份已存在 跨系统同步

等 workspace 投影和本地业务归属稳定后，再扩展 Hilbert device、plan、raw data、dataset 等资源同步。

  • 复用 PR-1 的 Hilbert service identity provider 和内存 sessionKey。
  • 同步或映射 Hilbert dc_device、dc_plan、raw_data、dataset。
  • 设计 default workspace 数据显式补绑到 Hilbert workspace 的审计流程。
  • 设计 Workspace 撤权 / 下线后的 access_status 和历史数据可见性策略。
03

推荐 PR 拆分

PR 主题 包含 不包含 完成情况
PR-1A Default Workspace Foundation 在现有 workspaces 表和 workspace.go 基础上改造： 新增 id=0 default workspace、source、upload_enabled、last_synced_at； API 先只保留 GET /workspaces 和 GET /workspaces/:id，返回 default。 不接 Hilbert；不做 /workspaces/sync；不改业务表 workspace_id；不接 Synapse 全局 selector。 已完成： workspace.go 已改为只读 GET；写路由已移除； V2 baseline 已加入 id=0 default、source、upload_enabled、last_synced_at； workspace 单测覆盖 default 返回、workspace_id=0 过滤和写路由不存在。
PR-1B Hilbert Workspace Sync Bootstrap 新增独立 HilbertConfig、Hilbert service identity provider、临时 code/password bootstrap、 内存 sessionKey、启动同步和 POST /workspaces/sync； 调用 GET /v1/console/workspace/list-available 后事务化 upsert 本地 projection。 不同步 device/plan/raw data/dataset；不把 admins/members 接入 Keystone 权限； 不做正式 Keystone-Hilbert 鉴权；不处理 workspace 撤权策略。 已完成： Keystone 已新增 HilbertConfig、Hilbert service identity provider、内存 sessionKey、启动 best-effort sync、POST /workspaces/sync 和事务化 Hilbert workspace upsert。 PR-1B 的 password bootstrap 是临时 provider，后续必须替换为 Hilbert 正式 Keystone 鉴权。
PR-1C Synapse Workspace Selector 删除组织管理入口；新增全局 Workspace Selector 和只读 Workspace 状态页； default 可选但标记本地 / 不可云同步，默认优先选择可上传 Hilbert workspace。 不改业务页面筛选参数；不提供 workspace 创建、编辑、删除表单；不自动迁移 default 数据。 未完成： 后端 default workspace 的只读 GET API 已就绪；Synapse 仍需要按全局 selector / 只读状态页接入。
PR-2 业务归属字段替换 所有 organization_id -> workspace_id NOT NULL DEFAULT 0，列表、统计、dashboard 同步改参。 不把 default 数据自动上传，不改 SOP/order/batch/task 的 Hilbert 语义。 未完成： 当前业务表仍大量使用 organization_id；robots 尚无 workspace_id。
PR-3 Factory 解耦 删除 orgCount，去掉 factory -> workspace 关系和 UI 文案。 不重命名表到 dc_factories，避免无收益 churn。 部分已有： V2 baseline 的 workspaces 已不含 factory_id； 但 factory 相关接口、统计和 Synapse 文案仍需按物理维度清理。
PR-4 Robot 设备归属 robots.workspace_id，workstation 同 workspace 校验，Synapse 设备页接 workspace selector。 不处理 Hilbert 设备同步。 未完成： 现有 robots 仍以 factory_id 为主要现场维度，尚未 workspace-scoped。
PR-5 主链路语义设计 SOP/order/batch/task/episode 与 Hilbert plan/raw-data/dataset 的设计、映射字段和 default 补绑策略。 不一次性替换任务派发和录制回调行为。 未完成： 当前任务、Episode、云同步链路已有本地执行和上传实现； 但尚未定义 Hilbert plan/raw-data/dataset 映射和 default 显式补绑流程。
PR-6 Hilbert 资源同步扩展 基于已有服务身份同步 device、plan、raw data、dataset，处理 workspace 撤权策略。 不回头兼容旧 organization 模型。 未完成： 依赖 PR-1B 的 service identity provider 和 PR-5 的主链路语义设计。
结合当前代码，PR-1A 已完成：default workspace 的后端基础能力已经落地，且不依赖 Hilbert。 PR-1B 已完成 Hilbert service identity bootstrap；PR-1C 再让 Synapse 使用新的只读 selector。 Robot / workstation 会牵动设备注册、Axon、任务派发，是独立风险面，不应混入 PR-1。
04

PR-1 决策锁定

PR-1 的目标是建立 Workspace 来源规则，而不是提供 Keystone 本地 Workspace 管理。 详细决策已拆分到独立文档： PR-1 Workspace 来源规则决策锁定。

当前实现进度：PR-1A / PR-1B 已完成。Keystone 后端已具备 id=0 default workspace、 只读 GET /workspaces / GET /workspaces/:id、V2 baseline schema、 POST /workspaces/sync、Hilbert service identity bootstrap 和事务 upsert 支撑。 Synapse selector 仍属于 PR-1C。
PR 锁定内容 状态
PR-1A Default workspace foundation：保留 id=0，Workspace API 只读，移除本地写路由。 已完成
PR-1B Hilbert workspace sync bootstrap：service identity provider、临时 password bootstrap、事务 upsert。 已完成
PR-1C Synapse workspace selector：删除组织管理入口，新增全局 selector 和只读状态页。 未完成

核心不变量

  • Hilbert 是 Workspace source of truth；Keystone 只保存可访问 Workspace 的本地投影。
  • workspaces.id=0 是 Keystone 保留 default workspace，不对应 Hilbert Workspace。
  • default workspace 允许本地采集和 Keystone MinIO 本地制品上传，但禁止进入 Hilbert / 云同步。
  • 云同步资格统一使用 workspace_id != 0 && source='hilbert' && upload_enabled=true。
  • Hilbert admins/members 第一阶段只展示，不驱动 Keystone 本地权限。
05

验收标准

每个阶段必须满足

  • OpenAPI / Swagger 与 handler 字段一致。
  • Synapse API wrapper、表单、筛选、详情字段一致。
  • Keystone 单元测试和构建通过。
  • 新增字段没有旧名残留在 runtime path。
  • default workspace 的本地可用性和云同步禁止规则有测试覆盖。

最终必须满足

  • 业务数据均可按 workspace_id 查询。
  • factory 不再影响 workspace 归属。
  • 设备不能跨 workspace 绑定数采员。
  • 一个 Keystone 可消费多个 Hilbert workspace。
  • workspace_id=0 的数据不会自动进入 Hilbert / 云同步。

PR-1 必须满足

  • 未配置 Hilbert 时，GET /workspaces 返回 id=0 的 default workspace，且 upload_enabled=false。
  • Hilbert 同步成功后，GET /workspaces 返回 default 加本地缓存的 Hilbert workspaces。
  • Hilbert 后续失败时，GET /workspaces 仍返回上次缓存加 default；手动 sync 返回失败。
  • Swagger 不暴露 workspace 创建、更新、删除接口。
  • Synapse selector 展示 default，但明确标记本地和不可云同步。

本地上传与云同步验收

  • default workspace 下允许本地采集、Axon transfer 上传 MCAP 到 Keystone MinIO、生成本地 Episode。
  • cloud sync worker 和任何 Hilbert raw data / dataset 创建路径必须拒绝 workspace_id=0。
  • 云同步资格统一使用 workspace_id != 0 && source='hilbert' && upload_enabled=true。
06

明确后置的问题

  • scene/subscene 是否最终变成 workspace-scoped 模板。
  • SOP 是否等价于 Hilbert dc_task，还是 Keystone 本地执行模板。
  • order 是否等价于 Hilbert dc_plan，还是 dc_plan 的本地执行投影。
  • batch 是否继续作为 Keystone 本地执行批次。
  • episode 与 Hilbert raw_data / dataset 的同步边界。
  • Hilbert admins/members 是否第一时间进入 Keystone 本地权限模型。
  • default workspace 数据如何显式补绑到 Hilbert workspace，以及需要记录哪些审计字段。
  • Hilbert 不再返回某个 workspace 时，是否新增 access_status 和历史数据可见策略。
  • Workspace 撤权后，未同步数据是否继续允许云同步，还是必须暂停等待人工处理。
这些问题不是不重要，而是不应该挡住第一阶段的归属边界迁移。 等 Hilbert workspace 投影和 workspace_id 成为稳定边界后，再逐个替换主链路语义。
