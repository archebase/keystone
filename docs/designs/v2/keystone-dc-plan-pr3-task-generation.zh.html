数采计划
接管 TASK
生成链路

核心矛盾：Hilbert dc_plan 已经成为生产主对象，但 Keystone runtime 仍依赖 order/batch/task 旧链路。PR-3 要让计划同步后自动补齐本地 task，同时用兼容壳稳住现有执行路径。

触发点同步 Workspace 的 dc_plan 后自动生成
主事实tasks.dc_plan_id 是新语义来源
兼容层order/batch/SOP/scene 只服务旧 runtime
失败策略单计划 blocked 不拖垮整批同步
01

背景与问题

PR-2 已经把 Hilbert dc_plan 投影到 Keystone，并提供 POST /workspaces/:workspace_id/dc-plans/sync 与 GET /dc-plans。 但是现有任务生产仍通过本地 orders / batches 创建， tasks.dc_plan_id 只是 schema 预留，runtime 尚未写入。

PR-3 的目标不是删除旧模型，而是把 Hilbert 数采计划变成 task 生成入口。 旧 order/batch/scene/SOP 字段继续存在，但只作为兼容壳，不能再承担业务事实来源。
现状
dc_plan 已同步；task 仍由本地 order/batch 手动创建；Axon config 仍读取旧字段。
变化
每次成功同步 Hilbert 计划后，Keystone 自动按 target_count 补齐 tasks。
边界
不上传 raw data、不删除 order/batch schema、不改变 Axon 录制回调协议。
02

目标与非目标

目标

  • SyncWorkspaceDCPlans 成功同步计划后自动生成或补齐本地 tasks。
  • 同一计划重复同步保持幂等，只新增 target_count - existing_count 的缺口。
  • 为计划创建/复用兼容 order 与稳定 batch，不破坏现有 runtime。
  • 按 operator + dc_device_id 找到或自动创建 current workstation。
  • task list/detail/config 暴露 dc_plan_id、workspace 和计划元信息。

非目标

  • 不在拉取数采计划时创建设备、机器人或采集员主数据。
  • 不删除 order/batch/schema 旧字段，不重写 Axon callback 协议。
  • 不把 target_duration 平均分配到单个 task。
  • 不迁移已经存在的 task 到新工位或新配置。
  • 不修改 dc_plan.cur_count / cur_duration，保持 Hilbert 投影语义。
03

方案总览

POST /api/v1/workspaces/:workspace_id/dc-plans/sync
  -> login Hilbert
  -> query dc_plan pages
  -> validate records
  -> transaction: upsert dc_plan projections
  -> for each returned plan:
       transaction:
         lock plan/order for generation
         resolve data_collector by operator
         resolve robot by device_id = dc_device_id
         ensure current workstation for robot + collector
         ensure plan compat factory / SOP / scene / subscene
         ensure compat order + stable batch
         create missing tasks up to target_count
  -> return sync summary + per-plan task_generation summary

task 生成只处理本次 Hilbert 返回并成功 upsert 的计划。本地已有但本次没返回的计划不动； 计划校验失败时不提交 plan upsert，也不会生成 task。

04

关键规则

触发与幂等

  • 触发点固定为 POST /workspaces/:workspace_id/dc-plans/sync，不新增显式 generate endpoint。
  • 每次同步后按最新 target_count 补齐 task，只新增缺口。
  • target_count 增大时补齐新增 task；减小时不删除、不取消、不改已有 task。
  • existing count 统计 tasks.dc_plan_id = ? AND deleted_at IS NULL 的所有状态 task。
  • soft-deleted task 不计入 existing count。

工位解析

Hilbert 字段 Keystone 映射 PR-3 行为
dc_plan.operator data_collectors.operator_id 必须已由 Workspace 级同步创建；缺失时该 plan blocked。
dc_plan.dc_device_id robots.device_id 直接按字符串匹配；PR-3 不使用 robots.asset_id 作为主映射。
operator + dc_device_id workstations 存在同一 current workstation 时复用；都未绑定时自动创建；绑定冲突时 blocked。
  • PR-3 不自动创建 robot 或 data_collector。
  • robot / data_collector 必须是 active，否则 blocked resource_inactive。
  • 若 robot 和 collector 都未绑定 current workstation，则自动创建 status='active' 的 workstation。
  • 自动创建工位名称为 hilbert_ws_<operator>_<dc_device_id>，过长时截断并加短 hash。
  • 自动创建工位要求 data_collectors.organization_id = dc_plan.workspace_id，不一致时 blocked workspace_mismatch。
  • 自动创建工位还要求 robots.metadata.hilbert_workspace_id = dc_plan.workspace_id；缺失或不一致时 blocked workspace_mismatch。
  • 自动创建工位的 factory_id 使用 dc_plan.dc_factory_id 对应的 plan compat factory，不使用 PR-2.5 的 workspace compat factory。

兼容 order / batch

  • 每个 dc_plan 一个 compat order，一个稳定 compat batch。
  • orders.target_count = dc_plan.target_count，每次同步跟随更新。
  • 若 compat order 已 completed / cancelled，generation blocked compat_order_closed。
  • batches.batch_id = dcplan_<dc_plan_id>，长期复用，不按同步次数创建新 batch。
  • batches.episode_count = dc_plan.target_count，每次同步跟随更新。
  • 若 compat batch 已 completed / cancelled / recalled，generation blocked compat_batch_closed。

兼容生产元信息

  • 按 dc_plan.dc_factory_id 创建/复用 plan compat factory stub，用于 task / order / batch / scene runtime 兼容。
  • PR-2.5 的 workspace compat factory 只用于 robots.factory_id 落库；plan compat factory 与 workspace compat factory 不要求相同。
  • 按 dc_plan.dc_type 创建/复用 compat SOP、scene、subscene。
  • sops.slug = hilbert_dc_plan_<dc_type>，version = 1.0.0。
  • scenes.name = Hilbert <dc_type>，subscenes.name = Default。
  • 这些旧字段只满足现有 joins 和 Axon config，不再表达真实业务元信息。

task 内容

  • 沿用现有 newPublicTaskID()，不把 plan ID 塞进 public task_id。
  • tasks.dc_plan_id 写入 Hilbert plan ID，local_dc_plan_id 保持空。
  • target_duration 只进入 task metadata，不平均分配，不控制 recorder 自动停止。
  • 已存在 task 一律不迁移；新补齐 task 使用最新 plan 快照。
{
  "source": "hilbert_dc_plan",
  "dc_plan_id": 1001,
  "workspace_id": 123,
  "dc_plan_sequence": 5,
  "target_count": 10,
  "target_duration": 600,
  "dc_type": "ego",
  "dc_device_id": 456,

06

事务与错误处理

场景 处理 响应
Hilbert 查询或 plan 校验失败 不提交 plan upsert，不生成 task。 503 或 5xx。
plan upsert 成功，单个 plan 缺 robot / collector 该 plan 不生成 task，其他 plan 继续。 200，plan summary 为 blocked。
robot / collector 当前绑定冲突 不自动拆绑，不生成 task。 200，reason workstation_binding_conflict。
单 plan 生成过程中 DB 写失败 回滚该 plan 的工位、compat 壳和 task 写入。 200 或 5xx，取决于错误是否可归类为业务 blocked。
并发同步同一 plan generation transaction 中锁定 plan 或 compat order 行，重新计算缺口。 幂等，不超额生成。
事务边界锁定为：本次 Hilbert 返回的 plans 先整批 upsert；之后每个 plan 独立事务生成 task。 单计划失败不回滚整个 workspace 的 plan 投影。
07

实施计划

  1. 在 services 或 handler 内新增 plan task generation service，避免把所有逻辑塞进 dc_plan.go。
  2. 扩展 DCPlanSyncResult 和 DCPlanSyncResponse，返回 task generation summary。
  3. 同步 flow 中 upsert plans 后，对本次返回的 plans 逐个调用 generation。
  4. 实现 resolve collector / robot / workstation；只自动创建 workstation，不创建 robot / collector。
  5. 实现 plan compat factory、SOP、scene、subscene、order、batch ensure 逻辑。
  6. 实现 task 缺口补齐、metadata snapshot、并发锁和 target_count 变化处理。
  7. 扩展 task list/detail/config response 和筛选参数。
  8. 补 handler/service 单测：首次生成、重复幂等、target_count 增大、target_count 减小、缺资源 blocked、绑定冲突、robot workspace mismatch、并发防超额。
08

验收标准

  • 同步一个包含 10 个 target 的 plan 后，Keystone 自动生成 10 个 pending task。
  • 重复同步同一个 plan 不新增 task。
  • Hilbert 将 target 从 10 调到 15 后，再同步只新增 5 个 task。
  • Hilbert 将 target 从 15 调到 8 后，再同步不删除 task，并在 summary 中暴露本地 existing 超过 target。
  • robot / collector 缺失时 plan blocked，其他 plan 正常生成。
  • robot + collector 存在但无 current workstation 时自动创建工位。
  • task list/detail 能按 workspace_id / dc_plan_id 查询并展示计划字段。
  • Axon GET /tasks/:id/config 对计划生成 task 仍返回兼容旧字段，并追加计划字段。
  • dc_plan.cur_count / cur_duration 不因本地 task 生成被修改。
