Hilbert 数据采集域的核心不是“工厂拥有一切”，而是 Workspace 承担权限和业务归属， DC Factory / Service Provider / Device Type 是全局字典， DC Plan 在一个 Workspace 内聚合字典和 Workspace 资源。

01

核心判断

Workspace-scoped

直接有 workspace_id，创建、查询、更新都通过 workspace 做权限收敛。

  • dc_project
  • dc_task
  • dc_device
  • dc_plan
Global Dictionary

没有 workspace_id，作为跨 workspace 可引用的基础资料。

  • dc_factory
  • dc_service_provider
  • dc_device_type
Plan Aggregation

dc_plan 属于 workspace，同时引用全局字典和同 workspace 下资源。

  • workspace_id
  • dc_factory_id
  • dc_project_id
  • dc_task_id
  • dc_device_id
对 Keystone 迁移最重要的结论：Hilbert 的 dc_device 属于 Workspace； dc_factory 不属于 Workspace。Keystone 应消费 Hilbert Workspace， 而不是在本地重新拥有 Workspace 管理权。
02

Workspace 的含义

Workspace 是权限边界，不是展示分组

workspace 表包含 admins_str 和 members_str。 Service 层提供 CanManageWorkspace、CanAccessWorkspace、 ListAccessibleWorkspaceIDs 三类能力，说明 Workspace 直接参与权限判断。

操作类别 权限语义 代码中的规则
管理 Workspace 系统管理员或 workspace admin CanManageWorkspace 检查系统管理员，再检查 admins_str
访问 Workspace 系统管理员、workspace admin 或 workspace member CanAccessWorkspace 同时检查 admins_str 和 members_str
未指定 workspace 查询业务数据 系统管理员查全部；普通用户只查可访问 workspace ListAccessibleWorkspaceIDs 给 repository 构造 workspace_id IN (...) 
Account
  ├─ system admin ────────────────> all workspaces
  └─ normal account
      ├─ workspace.admins_str ────> manage + access
      └─ workspace.members_str ───> access only
03

Workspace 直接拥有的业务实体

以下实体都在 DO 或 Controller DTO 中显式包含 workspaceId， Service 创建时校验 Workspace 存在和管理权限，查询时按 Workspace 访问权限过滤。

实体 表 / DO 归属字段 含义 关键约束
项目 dc_project workspace_id 一个 Workspace 下的数据采集项目。 创建和更新要求当前用户可管理所属 Workspace；查询按可访问 Workspace 过滤。
任务定义 dc_task workspace_id 一个 Workspace 下的采集任务类型或任务定义。 dc_plan 引用它时必须验证它属于同一个 Workspace。
设备 dc_device workspace_id 一个 Workspace 下的采集设备，包含设备名称、序列号和设备类型。 name 和 sn 全局唯一；dc_device_type_id 引用全局设备类型。
计划 dc_plan workspace_id 一个 Workspace 下的一次数据采集计划。 聚合 Workspace 内资源和全局字典资源；创建/更新要求 workspace admin。 
Workspace
  ├─ DCProject     (workspace_id)
  ├─ DCTask        (workspace_id)
  ├─ DCDevice      (workspace_id)
  └─ DCPlan        (workspace_id)
       ├─ references DCProject in same workspace
       ├─ references DCTask in same workspace
       └─ references DCDevice in same workspace
04

全局字典实体

这些实体没有 workspace_id，不是 Workspace 的子资源。 它们更像“采集域基础资料”，由计划或设备引用。

实体 表 / DO 是否属于 Workspace 被谁引用 语义
工厂 / 地点 dc_factory 否 dc_plan.dc_factory_id 数据采集发生的工厂、地点或场地字典。
服务商 dc_service_provider 否 dc_plan.dc_service_provider_id 执行或提供采集服务的服务商字典。
设备类型 dc_device_type 否 dc_device.dc_device_type_id 采集设备的类型字典。
采集类型 dctype service 常量 否 dc_plan.dc_type 如 umi、ego 一类的枚举值。
dc_factory 不拥有 dc_device。 设备属于 Workspace；工厂只是 Plan 的采集地点维度。
05

DC Plan 的聚合规则

dc_plan 是 Hilbert 数据采集域里最能体现归属关系的实体。 它自己属于 Workspace，同时引用全局字典和 Workspace 内资源。 

DCPlan
  ├─ workspace_id               -> owning workspace
  ├─ dc_factory_id              -> global DCFactory
  ├─ dc_service_provider_id     -> global DCServiceProvider
  ├─ operator                   -> account code; must access same workspace
  ├─ dc_project_id              -> DCProject in same workspace
  ├─ dc_task_id                 -> DCTask in same workspace
  ├─ dc_device_id               -> DCDevice in same workspace
  ├─ dc_type                    -> global collection type enum
  ├─ dc_date                    -> planned collection date
  ├─ target_count / cur_count
  └─ target_duration / cur_duration

创建计划时的校验顺序

  1. 校验 workspace_id 存在。
  2. 校验当前用户是系统管理员或 Workspace 管理员。
  3. 校验计划名称唯一。
  4. 校验 dc_factory_id 存在。
  5. 校验 dc_service_provider_id 存在。
  6. 校验 operator 账号存在且可访问该 Workspace。
  7. 校验 dc_project_id 属于同一个 Workspace。
  8. 校验 dc_task_id 属于同一个 Workspace。
  9. 校验 dc_device_id 属于同一个 Workspace。
  10. 校验 dc_type 和 dc_date 合法。
这套规则说明：Plan 的“归属”由 Workspace 决定； Factory、Service Provider、Device Type 只是被引用的维度，不参与 Plan 的权限边界。
06

前端上下文如何强化归属

Hilbert 前端有全局 Workspace Selector，业务页面通过 selectedWorkspaceId 作为查询 key 和请求参数。 这说明用户进入业务模块时，默认是在一个 Workspace 上下文中工作。 

WorkspaceSelector
  ├─ fetch available workspaces
  ├─ persist selectedWorkspaceId
  └─ business pages use selectedWorkspaceId
       ├─ list dc_project by workspaceId
       ├─ create dc_project with workspaceId
       └─ gate page by RequireAvailableWorkspace

因此，Workspace 不只是后端字段，也是前端导航和业务页面状态的全局上下文。

07

Keystone 的 Workspace 消费边界

Keystone 不作为 Workspace 的源头系统。真实 Workspace 由 Hilbert 管理，Keystone 只保存 Hilbert 可访问 Workspace 的本地投影；当 Hilbert 未配置或暂时不可用时，Keystone 使用 id=0 的 default workspace 作为本地兜底归属。

Workspace 类型 Keystone ID 来源 本地采集 云端 / Hilbert 同步
Default 0 Keystone 保留的本地真实行，不对应 Hilbert Workspace。 允许创建本地任务、生成 Episode，并允许 Axon 上传 MCAP 到 Keystone MinIO。 禁止；不能创建 Hilbert raw data / dataset，也不能进入云同步。
Hilbert 直接使用 Hilbert workspace.id 通过 Keystone 的 Hilbert service identity 拉取并缓存。 允许。 仅当 source='hilbert' 且 upload_enabled=true 时允许。 
Keystone workspaces
  ├─ id=0, source=default, upload_enabled=false
  │   └─ local-only collection and local artifact storage
  └─ id=<hilbert_workspace_id>, source=hilbert, upload_enabled=true
      └─ eligible for cloud / Hilbert sync

本地上传与云同步必须分开

Default Workspace 的“不可上传”只指不可进入 Hilbert / 云端同步链路。 axon_transfer -> Keystone MinIO 是本地制品上传，属于本地采集闭环； 它允许在 default workspace 下发生，否则离线采集和后续人工补绑都无法成立。

默认数据不能自动归属到 Hilbert

Default Workspace 下产生的任务和 Episode 没有 Hilbert 业务归属。 后续可以设计显式人工补绑流程，将选定数据迁移到某个 Hilbert Workspace； 但系统不能自动把 default 数据上传到任意 Hilbert Workspace。

权限投影不是权限执行

Keystone 可以展示 Hilbert 同步来的 admins_str 和 members_str， 但第一阶段不把这些字段接入 Keystone 本地权限模型。手动同步 Workspace 是 Keystone admin 操作，不由 Hilbert workspace admin 自动获得。

临时 Bootstrap 不是正式鉴权

PR-1B 可以临时用 Hilbert 的 code/password 登录流程获取 sessionKey，但代码边界必须抽象为 Hilbert service identity provider。 后续正式 Keystone-Hilbert 鉴权应替换该 password bootstrap，并让 Hilbert 审计能区分 Keystone 服务身份和人工管理员。

08

对 Keystone 迁移的直接启示

Keystone 当前实体 Hilbert 对齐对象 建议归属 说明
organizations workspace Hilbert 投影 + Default 兜底 删除本地组织概念；workspace_id 直接使用 Hilbert ID，0 保留给本地 default。
data_collectors Hilbert operator/account 在 workspace 内可访问 Workspace-scoped organization_id 改为 workspace_id；本地 API 可使用 0，云同步不可使用 0。
robots dc_device Workspace-scoped + 物理维度 新增 workspace_id；保留 factory_id 作为物理工厂维度，禁止跨 workspace 绑定。
factories dc_factory Global Dictionary 不再拥有 Workspace；可继续承载机器人、场景、设备编号的物理维度。
orders / batches / tasks / episodes dc_plan 及采集产物链路 Workspace-scoped 统一用 workspace_id 做归属和筛选；云同步前必须校验有效 Hilbert workspace。
scenes / subscenes 当前 Hilbert 无直接等价实体 待决策 更像物理环境模板，可暂时保留 factory_id，但需要单独定复用边界。
Keystone 不应该把 Factory 替换成 Workspace，也不应该本地管理 Workspace。 更准确的迁移方向是：organization -> Hilbert workspace projection， factory -> dc_factory / physical site， robot -> workspace-scoped device + factory physical dimension。
