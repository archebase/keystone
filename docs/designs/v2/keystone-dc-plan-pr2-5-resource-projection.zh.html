Keystone / Hilbert V2

Workspace 运营资源最小投影

PR-2.5 是 PR-3 的前置 PR：在同步 Workspace 时固定同步采集员、数采设备、设备类型和兼容 factory， 让 Hilbert dc_plan.operator 与 dc_plan.dc_device_id 能解析成本地执行资源。

入口POST /workspaces/sync 和启动同步
采集员Workspace admins/members 中的 enabled data supplier
设备robots.device_id = dc_device.id 字符串
边界只投影主数据，不生成 task，不改 Synapse
01

目标与非目标

目标

  • Workspace sync 成功后，本地具备 PR-3 生成 task 所需的最小 resource projection。
  • dc_plan.operator 可匹配 data_collectors.operator_id。
  • dc_plan.dc_device_id 可匹配 robots.device_id。
  • Hilbert dc_device_type 可匹配 robot_types.id，满足现有 robot schema。
  • 每个 Hilbert workspace 有一个 workspace compat factory，满足 robots.factory_id 必填约束。

非目标

  • 不在拉取数采计划时创建 robot、device 或 data collector。
  • 不生成 task，不创建 workstation；工位自动创建属于 PR-3。
  • 不拉取 raw data / dataset，不改 Hilbert 上传协议。
  • 不改 Synapse 页面，不做 scoped admin shell。
  • 不自动软删 Hilbert 消失的本地资源投影。
本文的 API 合约来自 Hilbert 后端代码：workspace list、account query、dc-device query 和 dc-device-type query 均已在代码中确认。
02

Hilbert API 来源

资源 Hilbert API 关键字段 / 参数 Keystone 用途
Workspace GET /v1/console/workspace/list-available id、name、admins、members 确定需要同步资源的 Hilbert workspace；admins + members 是账号 code 候选集合。
Account GET /v1/console/account/query code 精确查；支持 role、externalUserType、status、pageSize=-1 把 workspace 成员筛成 Keystone data collector。
DC Device GET /v1/data-collection/dc-device/query workspaceId、id、name、sn、dcDeviceTypeId 同步 Keystone robot 投影。
DC Device Type GET /v1/data-collection/dc-device-type/query id、name、description 同步 Keystone robot type 投影。

Hilbert dc_device.id 是 bigserial primary key，全局唯一；name 和 sn 也有全局唯一约束。 因此 Keystone 不需要把 workspace_id 拼进 robots.device_id。

03

本地映射规则

Data Collector

候选来源是当前 workspace 的 admins + members。逐个按 code 查 Hilbert account，只同步满足以下条件的账号：

role = external_user
externalUserType = data_supplier
status = enabled

实现可以逐个 code 精确查询，也可以一次拉取 enabled + external_user + data_supplier 后与 admins + members 求交集；两种实现的最终同步结果必须等价。

Workspace Compat Factory

factories.slug = "hilbert_workspace_<workspace_id>"
factories.name = "<workspace.name> / Hilbert Workspace <workspace_id>"
robots.factory_id = compat factory id

该 factory 只是 Keystone robots.factory_id 的旧 schema 兼容载体，不代表 Hilbert 真实存在 factory。 PR-3 还会按 dc_plan.dc_factory_id 创建 plan compat factory，用于 task / order / batch / scene runtime 兼容； 两类 compat factory 语义不同，不要求 ID 相同。

04

同步流程与事务边界

WorkspaceSyncService.Sync
  ensure default workspace
  login Hilbert service identity
  list available workspaces
  validate workspace list
  transaction: upsert all workspaces
  for each Hilbert workspace where id > 0:
    transaction:
      upsert workspace compat factory
      query workspace admins/members account detail
      upsert data_collectors
      query dc devices by workspaceId
      query/upsert required dc device types
      upsert robots
    append per-workspace resource summary
  • 资源同步是 workspace sync 的固定组成部分，不加 HILBERT_SYNC_RESOURCES 开关。
  • Workspace upsert 先独立提交；resource sync 按 workspace 单独事务。
  • 单个 workspace 资源同步失败，只写入 summary，不回滚已成功的 workspace projection。
  • workspace_id=0 是 default workspace，不触发 Hilbert resource sync。
  • 建议新增 WorkspaceResourceSyncService，由 WorkspaceSyncService 编排调用。
05

覆盖、冲突与消失资源

覆盖规则

  • 只覆盖 Hilbert 权威投影字段和 metadata。
  • data_collectors 不覆盖 email、password_hash、certification、status、last_login_at。
  • robots 不覆盖 status 和 asset_id。
  • robot_types 只覆盖 Hilbert source 的类型投影；已存在的非 Hilbert source 类型不自动接管。
  • Hilbert source 通过 model = hilbert_dc_device_type_<id> 或 capabilities.source = "hilbert" 识别。

冲突规则

  • 如果 robots.device_id 已存在且 metadata.source != "hilbert"，跳过并记录 robot_device_id_conflict。
  • 如果 Hilbert robot projection 的 metadata.hilbert_workspace_id 与当前 dc_device.workspaceId 不一致，跳过并记录 robot_workspace_conflict。
  • 如果 data_collectors.operator_id 已存在但不是 Hilbert projection，不覆盖本地账号，只记录冲突。
  • 如果 robot_types.id = dc_device_type.id 已存在但不是 Hilbert projection，跳过该 type 和依赖它的 robot，并记录 robot_type_id_conflict。
  • 理论上 Hilbert dc_device.id 全局唯一，不会在不同 workspace 复用；workspace conflict 是防御性校验。

消失资源

  • Hilbert 当前返回的资源：upsert，并更新 metadata.last_seen_at。
  • Hilbert 当前未返回的历史投影：保留原状，不自动 soft delete，不自动 retire。
  • 后续如需 stale resource cleanup，应另开显式管理或清理 PR。
06

Response Summary

只要 workspace 主流程成功，HTTP 仍返回 200。资源局部失败通过 resource_sync.workspace_results[].errors 暴露。

{
  "synced_count": 3,
  "default_included": true,
  "last_synced_at": "2026-07-09T10:00:00Z",
  "resource_sync": {
    "enabled": true,
    "collector_upserted_count": 8,
    "collector_skipped_count": 2,
    "robot_upserted_count": 12,
    "robot_type_upserted_count": 4,
    "factory_upserted_count": 3,
    "workspace_results": [
      {
        "workspace_id": 101,
        "collector_upserted_count": 3,
        "collector_skipped_count": 1,
        "robot_upserted_count": 5,
        "robot_type_upserted_count": 2,
        "factory_upserted": true,
        "errors": [
          {
            "resource": "collector",
            "external_id": "alice",
            "code": "not_data_supplier",
            "message": "workspace member is not an enabled data supplier"
          }
        ]
      }
    ]
  }
}
  • Hilbert login、workspace list、workspace upsert 失败仍走原有错误路径。
  • resource summary 必须能定位 workspace、资源类型、外部 ID、错误码和简短原因。
  • skipped 不等于 failed；非 data supplier、disabled、missing account 均可归入 skipped 并计数。
  • 启动同步没有 HTTP response，必须把同一 summary 打到日志，至少包含 workspace、collector、robot、robot type、factory 的 upsert / skipped / error 计数。
07

实现清单与测试

实现清单

  • 扩展 Hilbert client：account query、dc-device query、dc-device-type query。
  • 新增 WorkspaceResourceSyncService 和 resource summary DTO。
  • 扩展 WorkspaceSyncService.Sync()，在 workspace upsert 提交后逐 workspace 同步资源。
  • 补齐本地 upsert SQL：workspace compat factory、data collector、robot type、robot。
  • 更新 WorkspaceSyncResponse、Swagger 注释和生成后的 OpenAPI。
  • 启动 best-effort sync 复用同一 resource summary，并输出聚合日志。

测试范围

  • workspace upsert 成功后调用 resource sync；resource sync 失败不回滚 workspace。
  • 默认 workspace id=0 不触发 resource sync。
  • enabled external_user + data_supplier 被 upsert 为 data collector；其它成员 skipped。
  • dc-device-type 被 upsert 为 robot type；dc-device 被 upsert 为 robot，且 device_id 是 Hilbert ID 字符串。
  • workspace compat factory 按 workspace 创建或复用。
  • 新建 data collector / robot 默认 active；已存在记录不覆盖 status。
  • 非 Hilbert 本地 robot / data collector 冲突时 skip + error。
  • 非 Hilbert 本地 robot type ID 冲突时 skip type 和依赖 robot，并返回 robot_type_id_conflict。
  • Hilbert 消失资源不 soft delete；upsert 不覆盖本地运营字段。
PR-2.5 不要求 Synapse E2E、真实 Hilbert 联调或 Docker compose integration；风险集中在映射、事务边界、冲突语义和 summary。
