01

背景与问题

现有 App 已能采集 MCAP 并通过旧 Data SDK 上传，但任务平台仍围绕 batch、SOP 和 scene 建模，上传完成也没有形成 Keystone episode。

现状

  • SwiftPM 指向独立 data-sdk 仓库。
  • 设备绑定只保存 device_id，App 自行拼接三个 gRPC endpoint。
  • 任务通过 /batches、/batches/{id}/tasks 和 /sops 获取。
  • 多个本地采集可能复用一个代表性 task ID。
  • SDK CompleteUpload 当前只完成上传会话并写日志。

触发变化

  • Swift SDK 已归并到 Keystone，数据面改为火山云 TOS。
  • 首次初始化必须使用管理员签发的 device_auth_token。
  • Hilbert dc_plan 成为生产计划主对象。
  • task 由数采计划生成，并携带 dc_plan_id 与 workspace_id。
  • 生产数据需要通过 episode 留下可查询、可审计的持久事实。
本项目只面向全新环境部署：不迁移历史 batch、不兼容旧 SDK 上传快照、不回填历史 capture 或 episode。
02

目标与非目标

目标不是维持旧接口外观，而是收敛出一个小而稳定的 App interface，让任务、采集和上传保持一一对应。

目标

  • Keystone 成为 Swift SDK 唯一源码和发布入口。
  • App 使用完整 bootstrap 配置初始化设备。
  • 任务页面按数采计划分组、统计和展示。
  • 每次开始采集前锁定一个明确的 pending task。
  • 上传携带 task、dc plan、workspace 和 capture 上下文。
  • 上传完成后持久化 episode 并完成对应 task。

非目标

  • 不读取或迁移旧 SQLite batch 数据。
  • 不恢复旧 OSS/TOS multipart 状态。
  • 不兼容旧版无 token 设备初始化。
  • 不继续暴露 SOP、scene、subscene 等旧任务字段。
  • 不由 App 猜测 workspace 或从旧字段推导 dc plan。
  • 不在本次扩展云端质量和隐私处理流程。
03

目标架构

将当前巨型 ViewModel 中的 REST、SDK 和领域映射拆开，形成三个职责清晰的深模块。

REST ADAPTER

KeystonePlatformClient

负责登录、身份、任务、数采计划和 task 生命周期。只向 App 返回稳定领域模型，不泄漏 HTTP DTO。

DOMAIN MODULE

CaptureWorkflow

选择计划、锁定 task、开始采集、生成 capture 绑定、协调上传和完成。它是 UI 与后端之间的主要 interface。

SDK ADAPTER

KeystoneUploadAdapter

封装设备 bootstrap、ready 检查、上传事件和错误映射。App 不读取 SDK 私有配置文件。

SwiftUI View
  -> CaptureWorkflow
       -> KeystonePlatformClient  -> Keystone REST /api/v1
       -> CaptureEngine           -> local capture_session
       -> KeystoneUploadAdapter   -> Keystone Swift SDK -> TOS

设备初始化

设备 ID 不再是完整凭证。初始化入口改为可信 bootstrap 配置，一次性 token 只用于首次证明。

{
  "device_id": "260427000001",
  "device_auth_token": "kda_v1_...",
  "api":       { "scheme": "https", "host": "keystone.example.com", "port": 443 },
  "auth":      { "scheme": "https", "host": "keystone.example.com", "port": 50053 },
  "gateway":   { "scheme": "https", "host": "keystone.example.com", "port": 50053 },
  "deviceInit":{ "scheme": "https", "host": "keystone.example.com", "port": 50053 }
}
扫描 管理员签发的完整 bootstrap JSON，不再扫描裸 device ID。
初始化 调用 QiongcheDataGatewaySDK.saveConfigAndInit，SDK 向 Keystone 消费初始化权限。
持久化 API Key 进入 Keychain；普通 JSON 只保存 credential store 标记和 authoritative tags。
运行 后续启动仅调用 ready 检查，不重复提交已消费的 token。
禁止把 bootstrap JSON、device auth token、API Key、JWT 或 TOS STS 凭证写入 UserDefaults、日志、剪贴板或可导出的诊断文件。

07

采集与上传闭环

capture_session 的本地完整性检查保持不变，变化发生在业务绑定和上传完成后的持久化动作。

选择计划 用户选择一个未完成的数采计划。
锁定任务 App 获取计划内一个明确的 pending task，并创建 CaptureAssignment。
本地采集 task、dc plan、workspace 信息写入 metadata、MCAP task event 和 manifest。
本地验证 MCAP、质量报告、manifest 和 checksum 全部通过后才允许上传。
创建上传 SDK 请求携带 capture、task、dc plan 和 workspace 上下文。
TOS 直传 SDK 使用 Keystone 签发的短期 STS 完成单对象或 multipart 上传。
业务完成 Keystone 校验对象与任务上下文，创建 episode 并完成对应 task。
本地收尾 App 写入 uploaded marker；按本地策略决定是否删除 MCAP。
clientHints / rawTags
  capture_id   = local capture UUID
  task_id      = Keystone public task_id
  dc_plan_id   = Hilbert plan projection ID
  workspace_id = authenticated device workspace
  device_id    = authenticated device ID
  product      = ego_portal_lite
  relative_path= capture.mcap
08

Keystone 必补能力

仅替换 App SDK 依赖无法形成业务闭环。上传控制面必须理解 task 和 episode，而不能只维护内存 session。

CreateLogicalUpload 守卫

  • 验证 task_id 存在且未被其他 episode 使用。
  • 验证 task 的 dc_plan_id 与请求一致。
  • 验证计划 workspace 与设备 JWT principal 一致。
  • 将 task、plan、workspace 和 capture 上下文写入持久 upload session。

CompleteUpload 事务

  • 校验 TOS 对象存在、size 与 ETag 符合预期。
  • 以 capture ID 或 logical upload ID 保证幂等。
  • 创建 episode，复制 task 的 dc_plan_id。
  • 保存 bucket、object key、size、ETag 和上传时间。
  • 完成且只完成本次 capture 对应的 task。
如果仍使用 POST /tasks/complete {dc_plan_id, quantity}，只能表达“完成若干任务”，无法证明哪一个上传对象对应哪一个 task，因此不作为正式链路。

本地数据与 UI

由于是全新部署，可以直接建立新 schema 和新文案，不保留 batch 兼容字段。

区域改造内容
SQLite直接创建 task_numeric_id、task_id、dc_plan_id、workspace_id、episode_id 和 upload identifiers。
Capture metadataTaskBinding 改为 CaptureAssignment，不再写 assignment、batch、SOP 和 scene 字段。
任务首页显示计划名称、计划目标、已采集、上传中、已完成和剩余数量。
文件列表按数采计划筛选；详情显示 task ID、dc plan ID、workspace ID 和 episode ID。
设备设置展示设备 ID、初始化状态和 endpoint 摘要；不允许查看或编辑敏感 token。
术语业务“批次”全部改为“数采计划”；多文件操作称“批量上传”，不再代表领域对象。
10

错误与安全

错误必须告诉操作者下一步动作，同时避免泄露初始化和上传凭证。

可重试

  • Keystone 暂时不可达。
  • 短期 JWT 或 TOS STS 过期。
  • 网络中断、分片失败、HEAD 暂时失败。
  • 服务端 5xx 或明确标记 retryable 的错误。

不可重试

  • device auth token 无效或已消费。
  • task 不存在、已完成或已绑定 episode。
  • dc plan 与 task 不匹配。
  • 设备 workspace 与计划 workspace 不一致。
  • 本地 checksum 或 manifest 校验失败。

12

验收标准

验收以数据库、对象存储和 App 三方事实一致为准，而不是只看 SDK 返回 completed。

App 只能使用带有效 device auth token 的 bootstrap 完成首次初始化。
App 不读取或展示明文 API Key、JWT、STS 或 bootstrap token。
任务列表和 UI 不再出现 batch、SOP、scene 领域字段。
每个本地 capture_session 持久化唯一 task、dc plan 和 workspace 绑定。
TOS object metadata 与 App capture、task、plan 信息一致。
每次上传成功产生且只产生一个 episode。
episode 的 dc_plan_id 与对应 task 完全一致。
完成一个上传只更新对应 task，不批量完成其他 pending task。
重复 CompleteUpload 不创建重复 episode，返回同一业务结果。
真机退出重进后可查询已完成数据，App、Keystone 与 TOS 状态一致。
设计状态：方向锁定。全新环境部署，无历史迁移；Keystone 上传闭环完成后再进入 ego-portal-lite 实施。
