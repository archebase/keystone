Keystone V2 / PR-4 / 实现决策锁定

EPISODE
锁定计划
直达上传

核心矛盾：task 已由 Hilbert 数采计划生成，但 episode 与直传链路仍没有把计划 ID 作为唯一业务元信息入口。PR-4 要把计划上下文从 task 固化到 episode，并在上传前强校验。

创建task 计划字段复制到 episode
守卫计划存在且 workspace_id > 0
传输raw_tags 与 client_hints 双写
失败业务前置缺失直接不可重试
01

背景与核心判断

PR-2 已建立 Hilbert dc_plan 投影以及 tasks / episodes 的计划字段； PR-2.5 补齐 Workspace 运营资源最小投影；PR-3 已让计划同步后生成带 tasks.dc_plan_id 的本地执行 task。剩余断点位于 episode 创建和云上传。

PR-4 的唯一业务事实入口是 episodes.dc_plan_id 指向的非删除 Hilbert 计划投影。 workspace_id 从该投影派生；order、batch、scene 等旧字段只保留为本地执行兼容和诊断信息，禁止回退解析。
02

目标与非目标

目标

  • 新 episode 创建时从 task 复制 dc_plan_id 和 local_dc_plan_id。
  • Episode API 暴露最小计划上下文，便于查询与排障。
  • 自动同步与手动同步共用同一个 Hilbert 上传守卫。
  • 上传时将 dc_plan_id、workspace_id 同时写入 raw_tags 和 client_hints。
  • 计划前置条件失败时生成清晰、不可重试的 sync failure。

非目标

  • 不修改 data-gateway proto。
  • 不修改 Axon 协议，也不要求 Axon 上传计划 ID。
  • 不支持仅有 local_dc_plan_id 的 Hilbert 上传。
  • 不回填、不迁移历史 episode，也不在上传时从 task 补推导计划。
  • 不删除 order/batch runtime，不改变 sync_logs schema。
03

端到端数据流

Hilbert dc_plan projection
  -> PR-3 task generation writes tasks.dc_plan_id
  -> Axon transfer completion creates episode
       copy task.dc_plan_id       -> episodes.dc_plan_id
       copy task.local_dc_plan_id -> episodes.local_dc_plan_id
  -> auto sync or manual sync enters the same worker path
  -> load episode + non-deleted dc_plan projection
  -> enforce Hilbert upload guard
  -> raw_tags[dc_plan_id, workspace_id]
  -> client_hints[dc_plan_id, workspace_id]
  -> data-gateway upload
持久事实
episodes.dc_plan_id 与 episodes.local_dc_plan_id 是创建时快照；不新增 episodes.workspace_id。
上传派生
workspace_id 每次从匹配的、未删除的 dc_plan.workspace_id 读取。
禁止回退
缺少计划字段时，不允许从 task、order、batch、scene、sidecar 或历史 raw tags 猜测。
04

Episode 创建与 API

创建写入

在 internal/api/handlers/transfer.go 的 transfer completion 事务中，扩展 task 查询结果， 读取 tasks.dc_plan_id 和 tasks.local_dc_plan_id，并将两者加入现有 INSERT INTO episodes。字段只做原值复制，不增加额外解析逻辑。

Task 状态Episode 创建后续 Hilbert 上传
有 dc_plan_id复制 Hilbert 计划 ID。通过计划与 Workspace 守卫后允许。
仅有 local_dc_plan_id允许创建并复制本地计划 ID。不可上传 Hilbert。
两个字段都为空仍允许本地创建 episode。不可上传 Hilbert。

Episode API 最小扩展

Episode list/detail response 增加以下字段；Workspace 与计划展示字段通过 dc_plan 左连接派生：

{
  "dc_plan_id": 1001,
  "local_dc_plan_id": null,
  "workspace_id": 123,
  "dc_plan_name": "Ego collection batch A",
  "dc_type": "ego"
}

PR-4 不新增 episodes.workspace_id 持久列，也不扩大 Episode API 到完整计划详情。

05

Hilbert 上传守卫

syncEpisodeUploadRow 与 processEpisodeWithMode 的查询结果必须带上 episode 计划字段以及 匹配计划的 Workspace/展示元信息。自动队列和手动触发不预过滤无计划 episode，而是在 worker 中执行同一守卫， 确保 sync_logs 留下明确失败记录。

守卫顺序条件结果
1episodes.dc_plan_id 非空且大于 0。否则不可重试失败。
2存在 ID 匹配且 deleted_at IS NULL 的 dc_plan。否则不可重试失败。
3dc_plan.workspace_id > 0。否则不可重试失败；default Workspace 禁止上传。
local_dc_plan_id 只是本地计划关联。即使它存在，也不能替代 Hilbert dc_plan_id 通过守卫。

错误文案

episode 4181 missing dc_plan_id
episode 4181 has local_dc_plan_id 27 but Hilbert upload requires dc_plan_id
dc_plan 1001 not found or deleted
dc_plan 1001 has invalid workspace_id 0

这些错误使用现有 newNonRetryableSyncError / wrapNonRetryableSyncError 分类， 由现有失败流程写入 sync_logs，不增加新列或新状态。

06

上传元信息契约

双通道写入

键raw_tagsclient_hints来源
dc_plan_id必须必须episodes.dc_plan_id
workspace_id必须必须dc_plan.workspace_id

两个值按十进制字符串传输，键名固定使用 dc_plan_id 和 workspace_id。 data-gateway 已有 CreateLogicalUploadRequest.client_hints 和 CompleteUploadRequest.raw_tags，因此不改 proto。

Keystone 内部改动

  • 扩展 dpRawTagContext 或等价输入，让 buildDPDirectRawTags 注入两个计划 tag。
  • 调用 cloud.UploadRequest 时，通过已有 ClientHints map 传入相同键值。
  • 现有 uploader 继续自动合并 episode_id 与 source=keystone-edge。

旧 raw tags 的定位

现有 order_name、batch_id、scene、subscene、 sop_slug、采集员和 robot type 等 tag 本 PR 不删除。它们用于诊断、检索和兼容观察， 但 Hilbert raw data / dataset 归属必须只认 dc_plan_id 与 workspace_id。

07

实施步骤

  1. 扩展 transfer handler 的 task row 与 episode insert，复制两个计划字段。
  2. 扩展 episode handler 的 row、查询和 response，返回五个最小计划字段。
  3. 扩展 syncEpisodeUploadRow 及其 SQL，加载 episode 计划字段和非删除 dc_plan 上下文。
  4. 在公共上传路径、解析制品和创建 uploader 之前执行 Hilbert 上传守卫。
  5. 扩展 raw tag 上下文，加入 dc_plan_id、workspace_id。
  6. 在 cloud.UploadRequest.ClientHints 中加入相同键值。
  7. 补充窄范围 handler/service 单测，并运行相关 Go package tests。

本 PR 没有历史迁移和数据回填，因此不需要额外 migration，也没有批处理或回滚脚本。 代码回滚后，新写入的 episode 计划字段可以保留，不影响旧 runtime。

08

测试矩阵

测试断言
transfer handler 创建 episodetask 的 dc_plan_id / local_dc_plan_id 原值写入 episode。
worker 缺 dc_plan_id返回不可重试错误；仅有 local plan 时错误明确指出 Hilbert 要求。
计划不存在或已删除返回不可重试错误，不创建 logical upload。
workspace_id = 0返回不可重试错误，不调用 data-gateway。
raw tags包含字符串形式的 dc_plan_id / workspace_id，旧诊断 tags 仍保留。
client hintsCreateLogicalUpload 收到相同的两个键值。

不扩展到全量 sync worker 回归矩阵；风险集中在 episode 创建复制、上传前置校验和两处 map 注入，测试与改动面保持一致。

09

验收标准

  • 按计划创建的 task 完成录制后，新 episode 持久化相同的 dc_plan_id。
  • Episode list/detail 可看到 dc_plan_id、local_dc_plan_id、workspace_id、dc_plan_name、dc_type。
  • 合法 Hilbert episode 上传时，raw_tags 和 client_hints 都包含计划与 Workspace ID。
  • 无 Hilbert 计划、计划已删除、计划不存在或 default Workspace 的 episode 均产生不可重试 sync failure。
  • 自动同步与手动同步行为一致，失败不被静默预过滤。
  • 仅有 local plan 的 episode 可以留在本地，但不能进入 Hilbert。
  • 历史 episode 不回填，PR-4 不承诺其可上传。
  • data-gateway proto、Axon 协议、sync_logs schema 均无变化。
