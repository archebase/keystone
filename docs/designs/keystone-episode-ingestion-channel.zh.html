接入与存储在创建时成对写入；Hilbert ID 在注册后只写一次。三者都不能由客户端自报或被重试改写。

01

背景与问题

Keystone 当前有两条独立的 Episode 创建路径，但 episodes 表既没有结构化字段记录哪条路径完成了创建，也没有记录源数据位于 MinIO 还是 Keystone TOS。云同步注册出的 Hilbert Raw Data ID 也只被临时编码进同步日志，无法形成稳定的 Episode 级关联。

文档状态：已实现，待发布验证。范围覆盖 Keystone 数据库、Episode 创建路径与 Sync Worker；迁移序列为 v2 / 000003。

Path A

Axon Transfer

axon_transfer 通过 WebSocket 上报 upload_complete。Keystone 验证 MinIO 中 MCAP 与 sidecar 均存在后，在 transfer handler 的事务内创建 Episode。

Path B

Data Gateway

Data Gateway 兼容服务在 gRPC CompleteUpload 成功时，将直传 TOS 的对象信息与任务绑定，并在同一业务事务内创建 Episode。

当前 Sync Worker 会临时写入 sync_logs.destination_path = "hilbert:raw_data_id:..." 以支持失败重试；同步成功后该值会被云端 object key 覆盖，Raw Data ID 随之丢失。

为什么需要两个独立字段

现有位置 示例 实际含义
episode.metadata.source dgwcompat 当前实现与对象存储定位提示；QA、云同步仍用它识别 TOS。
client_hints.source ego-portal 客户端产品来源，不是 Keystone 接入接口。
新字段 ingestion_channel 唯一表示“哪条 Keystone 接入通道创建了 Episode”。
新字段 storage_backend 唯一表示 Episode 原始数据在 Keystone 侧的存储后端。
新字段 hilbert_raw_data_id 持久表示 Episode 在 Hilbert 注册得到的 Raw Data 外部身份。
02

目标与非目标

本次必须完成

  • 为 episodes 增加不可空、无默认值的接入通道与存储后端列。
  • 增加可空、写入后不可变的 hilbert_raw_data_id。
  • 准确回填所有历史 Episode 的两个字段，不保留 unknown。
  • 让两条生产写入路径显式写入各自固定的字段组合。
  • 保持同通道重试幂等，拒绝跨通道完成。
  • 提供 schema 可回滚迁移，明确回滚前必须导出新增 Raw Data ID 映射，并覆盖关键验收场景。

明确不做

  • 不在 Episode、Data Ops、QA、Sync 或 Task API 中返回这三个字段。
  • 不增加列表筛选、统计接口或数据库索引。
  • 不允许客户端、sidecar、raw tags 或 client hints 指定任一字段。
  • 不使用 storage_backend 驱动 QA、Sync Worker 或下载路由。
  • 不删除或重命名现有 metadata.source。
  • 不顺带重构 TOS / MinIO 对象定位逻辑。
  • 不调用额外 Hilbert 查询接口回填历史成功记录的 Raw Data ID。
  • 不修改 v2 initial schema 或旧版 migrations 目录。
03

领域定义与不变量

接入通道是负责在上传完成时创建 Episode 的 Keystone 接口或协议；存储后端是 Episode 原始数据在 Keystone 侧的对象存储；Hilbert Raw Data ID是云同步注册成功后产生的外部实体标识。前两者是创建时事实，第三者是延迟建立的一对一外部关联。

服务端权威 接入与存储由创建路径成对写死，Raw Data ID 只接受 Hilbert RegisterRawData 返回值；任何客户端载荷都不参与计算。
创建后不可变 Episode 已存在时不改写接入通道或存储后端；Raw Data ID 允许从 NULL 变为正整数一次，之后不可修改。
同通道幂等 来自原通道的重复完成继续执行现有幂等校验，不创建重复 Episode。
跨通道冲突 另一个通道尝试完成同一 task 时拒绝本次完成，不覆盖先创建者。
后续流程无关 QA、人工审核、从 MinIO 同步到云端等动作均不得改变这两个创建时事实。
不是副本清单 storage_backend 只描述 Keystone 原始数据后端；Axon Episode 云同步后即使另有云端副本，该值仍为 minio。
NULL 是合法状态 尚未注册、从未同步以及无法恢复 ID 的历史成功 Episode 均保持 hilbert_raw_data_id = NULL。
04

数据模型

ingestion_channel ENUM(
  'axon_transfer',
  'data_gateway'
) NOT NULL
COMMENT 'Keystone ingestion path that created the episode'

storage_backend ENUM(
  'minio',
  'keystone_tos'
) NOT NULL
COMMENT 'Keystone storage backend holding source episode data'

hilbert_raw_data_id BIGINT NULL
COMMENT 'Hilbert raw data ID assigned during cloud sync'
  1. 创建字段无默认值：新增写入路径忘记通道或后端时必须立即失败。
  2. 创建字段不允许 NULL：历史与新增数据都必须拥有确定通道和存储后端。
  3. Raw Data ID 允许 NULL：只有 Hilbert 注册成功后才产生，不能在 Episode 创建时伪造占位值。
  4. ENUM + 组合 CHECK：列值和两组固定映射都由数据库约束；新增通道或后端必须同时修改 schema、代码与测试。
  5. 不建索引：第一版没有线上查询消费者，且当前值基数很低。
  6. 正数 CHECK：Raw Data ID 只能为 NULL 或正整数；不建立外键或唯一索引。

允许组合

ingestion_channel storage_backend 固定写入位置 语义边界
axon_transfer minio handlers.TransferHandler.onUploadComplete 原始 MCAP / sidecar 位于 Keystone MinIO；后续云同步不改变该值。
data_gateway keystone_tos dgwcompat.gatewayService.completeBusinessUpload 原始数据位于 Keystone 管理的 TOS；不表示客户端产品或云同步目标。
storage_backend 第一版只记录事实，不参与对象读取路由；现有 metadata 与 bucket 判断逻辑保持不变。

Hilbert Raw Data ID 生命周期

阶段 字段值 规则
Episode 创建 NULL 本地数据尚未在 Hilbert 注册。
RegisterRawData 成功 Hilbert 返回的正整数 在获取上传凭证和传输对象之前立即持久化。
上传或 Finish 失败 保持已写入 ID 下次重试复用，不重复注册 Raw Data。
同步完成 保持已写入 ID 与 cloud_synced、object key 分别承担实体关联和状态/位置职责。
历史成功记录 允许 NULL 旧同步日志中的临时 ID 已被 object key 覆盖，本次不远程反查。
05

写入与并发流程

两条路径都在 MySQL 中先对 task 行执行 FOR UPDATE。因此同一 task 的并发完成会串行化：先提交者创建 Episode 并锁定字段组合，后到者读取既有通道并进入幂等或冲突分支。

新 Episode 创建

01 / RECEIVE 接收 upload_complete 或 CompleteUpload。
02 / LOCK 在业务事务内锁定 task，并重新检查任务状态与归属。
03 / RESOLVE 从当前服务端路径确定固定的接入通道与存储后端，不读取客户端字段。
04 / PERSIST 在 INSERT INTO episodes 中显式写入接入通道与存储后端；Hilbert ID 初始为 NULL。

Transfer 路径

对象路径重复检查也必须验证通道。 当前 transfer 会先按 mcap_path / sidecar_path 判断对象是否已落库。修改后，任何被当作幂等成功的既有记录都必须先确认其通道为 axon_transfer。
创建时成对写入 axon_transfer / minio。 task 维度的既有 Episode 查询增加 ingestion_channel；同通道重试不改写 storage_backend，值不同则回滚事务并记录结构化冲突日志。
跨通道冲突不发送 upload_ack。 现有 transfer 协议没有负向 ACK。该分支拒绝数据库完成、不更新 task，并依赖错误日志暴露异常；重复上报风险纳入运维观察。

Data Gateway 路径

创建时成对写入 data_gateway / keystone_tos。 completedUploadEpisode 增加通道字段，按 task 查询既有 Episode 时一并读取 ingestion_channel；同通道重试不改写 storage_backend。
先验证通道，再执行现有幂等内容校验。 只有既有值为 data_gateway 时，才继续校验 object key、file size、duration、checksum、upload identity 与 ETag。
跨通道返回 gRPC FailedPrecondition。 不更新 task，不修改 Episode，并保持事务回滚。

行为矩阵

既有 Episode 本次入口 结果 数据变化
无 axon_transfer 创建并正常 ACK 写入 axon_transfer / minio
无 data_gateway 创建并完成 gRPC 请求 写入 data_gateway / keystone_tos
axon_transfer axon_transfer 按现有规则幂等成功 两个字段均不变
data_gateway data_gateway 通过内容校验后幂等成功 两个字段均不变
axon_transfer data_gateway FailedPrecondition 无
data_gateway axon_transfer 记录冲突，不发送 ACK 无

Hilbert 注册与重试

优先读取 episodes.hilbert_raw_data_id。 syncEpisodeUploadRow 加载可空字段；已有正整数时直接用于获取凭证和完成上传，不再调用 RegisterRawData。
兼容恢复旧 sync_logs 前缀。 Episode 字段为空时，继续扫描 hilbert:raw_data_id: 前缀；找到后先回填 Episode，再继续本次重试。
新注册 ID 在网络上传前落库。 RegisterRawData 返回后立即在一个本地事务中执行 Episode write-once 更新，并把同一 ID 写入当前 sync log 作为失败恢复检查点；提交后才获取凭证、读取源对象、上传并调用 FinishRawDataUpload。
不同 ID 是数据冲突。 若 Episode 已保存另一个正整数，不覆盖旧值；本次同步失败并记录 episode、existing 与 incoming ID。

Raw Data ID 原子写入契约

UPDATE episodes
SET hilbert_raw_data_id = :incoming_id
WHERE id = :episode_id
  AND hilbert_raw_data_id IS NULL
  AND deleted_at IS NULL;

-- affected = 1：首次写入成功。
-- affected = 0：回读字段；相同 ID 视为幂等，不同 ID 返回不可重试冲突。
-- 同一事务再写当前 sync_logs.destination_path 恢复前缀，然后提交。
06

迁移与回滚

当前运行时只嵌入 internal/storage/database/migrations/v2/*.sql，最新版本为 000002。本设计新增独立的 000003_episode_provenance up/down 文件，在同一迁移中加入三个字段，不修改已经发布的 initial schema。

Up migration

-- 1. 先允许 NULL，避免在历史行尚未分类时写入错误默认值。
ALTER TABLE episodes
  ADD COLUMN ingestion_channel
    ENUM('axon_transfer', 'data_gateway') NULL
    COMMENT 'Keystone ingestion path that created the episode'
    AFTER local_dc_plan_id,
  ADD COLUMN storage_backend
    ENUM('minio', 'keystone_tos') NULL
    COMMENT 'Keystone storage backend holding source episode data'
    AFTER ingestion_channel,
  ADD COLUMN hilbert_raw_data_id BIGINT NULL
    COMMENT 'Hilbert raw data ID assigned during cloud sync'
    AFTER storage_backend;

-- 2. dgwcompat 创建的历史行都有该 metadata 标记。
UPDATE episodes
SET ingestion_channel = 'data_gateway',
    storage_backend = 'keystone_tos'
WHERE JSON_UNQUOTE(JSON_EXTRACT(metadata, '$.source')) = 'dgwcompat';

-- 3. 当前其余生产记录均来自 transfer 路径。
UPDATE episodes
SET ingestion_channel = 'axon_transfer',
    storage_backend = 'minio'
WHERE ingestion_channel IS NULL;

-- hilbert_raw_data_id 不做猜测式回填；无法恢复的历史记录保持 NULL。

-- 4. 收紧最终契约：无 NULL、无 DEFAULT。
ALTER TABLE episodes
  MODIFY COLUMN ingestion_channel
    ENUM('axon_transfer', 'data_gateway') NOT NULL
    COMMENT 'Keystone ingestion path that created the episode',
  MODIFY COLUMN storage_backend
    ENUM('minio', 'keystone_tos') NOT NULL
    COMMENT 'Keystone storage backend holding source episode data',
  ADD CONSTRAINT chk_episodes_provenance_pair CHECK (
    (ingestion_channel = 'axon_transfer' AND storage_backend = 'minio')
    OR
    (ingestion_channel = 'data_gateway' AND storage_backend = 'keystone_tos')
  ),
  ADD CONSTRAINT chk_episodes_hilbert_raw_data_id_positive CHECK (
    hilbert_raw_data_id IS NULL OR hilbert_raw_data_id > 0
  );

Down migration

-- 破坏性回滚：执行前导出 episode_id / hilbert_raw_data_id 映射。
ALTER TABLE episodes
  DROP CHECK chk_episodes_hilbert_raw_data_id_positive,
  DROP CHECK chk_episodes_provenance_pair,
  DROP COLUMN hilbert_raw_data_id,
  DROP COLUMN storage_backend,
  DROP COLUMN ingestion_channel;
Deployment Rule

迁移期间必须停止旧版本写入

最终两列均无默认值，旧版 Keystone 在迁移完成后无法创建 Episode。本版本不支持与旧实例重叠的滚动发布：先阻断 Episode 完成流量并停止旧实例，再由新实例执行迁移和启动服务；验证通过后恢复流量。

Backfill Invariant

迁移完成后零空值

发布验证必须确认接入通道与存储后端的 NULL 计数均为零，并分别抽样检查两类历史组合。hilbert_raw_data_id 允许为 NULL，不做猜测式填充。

07

兼容性与权衡

保留 metadata 的路由职责

metadata.source = dgwcompat 当前仍被 QA 和 sync worker 用于识别 TOS 对象。两个新列只记录溯源事实，不能在本次删除旧 metadata 或让下游切换路由依据。

缓解：明确记录字段与路由信息的职责；本次不让下游改读新列。

MySQL ALTER / UPDATE 锁表

增列、全表回填和收紧 NOT NULL 可能对较大的 episodes 表产生锁等待或执行时间压力。

缓解：发布前统计行数与 metadata 分布，在维护窗口执行并观察 migration 日志。

Transfer 冲突可能重复上报

WebSocket 协议只有成功 ACK，没有对应的服务端拒绝消息。拒绝跨通道完成后，客户端可能继续重试。

缓解：记录带 task、existing、incoming 的明确错误日志；第一版不扩展 axon 协议。

未来新增通道或后端需要迁移

ENUM 强约束意味着第三条创建路径或存储后端不能只发布代码，必须先扩展列值。

缓解：把 schema、写入常量、冲突测试作为新增通道的统一交付单元。

固定组合需要端到端守卫

当前通道与后端是一一映射；只检查通道会把错误的存储后端误判为幂等成功。

缓解：数据库使用组合 CHECK；两条创建路径在所有幂等分支同时读取并验证通道与后端。

历史成功记录无法完整回填

旧同步成功后，sync_logs.destination_path 已从临时 Raw Data ID 变为 object key，本地没有可靠逆向映射。

缓解：字段保持可空；本次只恢复仍带 ID 前缀的失败或进行中记录，不猜测、不远程扫描。

Hilbert 注册与本地写入无法原子提交

RegisterRawData 是外部副作用；若 Hilbert 成功后数据库写入失败，无法用本地事务撤销注册。

缓解：先记录包含 Episode 与 Raw Data ID 的运行日志，再用一个本地事务写 Episode 和当前 sync log，失败即停止上传。若整个数据库事务无法提交，远端注册仍可能成为孤儿，需依赖日志或 Hilbert 对账人工恢复；本次不声称跨系统 exactly-once。

已拒绝的备选方案

方案 拒绝原因
字段名使用 source 与 metadata 和 client hints 中已有的两种 source 含义冲突。
只保存在 metadata 缺少非空与枚举约束，语义已被对象存储判断复用，不能作为清晰的审计事实。
VARCHAR(32) 允许拼写漂移；新增真实通道本来就必须改代码，配套迁移是可接受约束。
为两个字段设置默认值 会把未来忘记适配的新写入路径静默误分类。
字段名 source_storage_backend 名称过长；keystone_tos 已明确排除云同步目标，最终采用更直接的 storage_backend。
Raw Data ID 只保存在 sync_logs 一次 Episode 可有多次同步尝试，且成功日志会把 destination 覆盖成 object key；外部实体关联应归 Episode 所有。
hilbert_raw_data_id NOT NULL 未同步 Episode 尚无 Hilbert 实体，历史成功记录也无法可靠恢复，非空约束会迫使伪造数据。
保留 NULL 或 unknown 现有历史数据已有足够证据完成分类，不应永久降低字段可信度。

实施拆分

数据库迁移 新增 v2 版本 000003 的 up/down SQL；加入三个字段，完成历史分类、前两列非空收紧、组合/正数 CHECK 与破坏性回滚提示。

迁移后数据库核验

SELECT ingestion_channel, storage_backend, COUNT(*)
FROM episodes
GROUP BY ingestion_channel, storage_backend;

SELECT COUNT(*) AS missing_provenance
FROM episodes
WHERE ingestion_channel IS NULL
   OR storage_backend IS NULL;

SELECT
  CASE WHEN hilbert_raw_data_id IS NULL THEN 'unassigned' ELSE 'assigned' END AS hilbert_link_state,
  COUNT(*)
FROM episodes
GROUP BY hilbert_link_state;

先识别，再锁定。

Episode 的接入通道与存储后端是创建时事实，由 Keystone 可信写入并受数据库强约束；Hilbert Raw Data ID 是同步阶段形成的外部关联，允许为空但一经写入不可替换。第一版只建立这条可靠溯源链，不扩张 API、查询或存储路由范围。
